# P2 运营效率与管理分析总体设计

## Architecture and Ownership

P2 沿用现有 monorepo 和统一分析内核：

- `packages/db` 保存经营事实、容量有效期历史并执行机构/校区过滤和聚合。
- `packages/api` 用 Zod 定义统一查询、保存筛选和 CSV 导出契约，按当前角色选择允许的维度。
- `apps/web` 提供分析筛选、多维比较、资源视图和即时导出，只展示服务端已裁剪的数据。
- 父任务维护公共口径和集成验收；资源利用、经营对比、保存筛选/导出分别由独立子任务交付。

## Current-Stage Boundary

当前阶段的完成证据必须可以由仓库和本地环境复现：

- 数据库 migration、fixture 和 PostgreSQL 集成测试；
- API 合同、权限测试、类型检查和静态检查；
- 生产构建及桌面/390px 浏览器验证。

对象存储、恶意文件扫描、生产调度、外部投递和生产等量数据不满足该条件，因此不进入当前 P2 架构依赖。

## Shared Data Principles

- 机构和校区范围由当前会话成员关系在服务端解析；页面、下钻、保存筛选和导出都重新授权。
- 负责人、教师容量和班级容量等可变配置使用有效期历史；转化、课消、资金和续费机会等经营事实不可静默改写。
- 时间区间统一左闭右开，业务自然日按 `Asia/Shanghai`，金额使用整数分。
- 所有显示与 CSV 复用同一查询服务和指标版本；前端不计算第二套指标。
- 新表和列采用 additive migration；历史覆盖不足时返回数据质量信息，不伪造回填。

## Remaining Delivery Graph

1. 资源利用分析先固化教师/班级容量历史及聚合契约。
2. 多维经营对比页面整合已完成的核心指标、财务指标和资源指标。
3. 保存筛选与即时 CSV 在查询契约稳定后复用同一服务端路径。
4. 父任务执行跨角色、跨校区、权限收回、指标版本和浏览器集成验收。

## Reporting Design

- 保存筛选是成员私有配置，只保存受控字段，不保存权限快照。
- 应用保存筛选时重新校验报表类型、维度、时间范围、校区和当前权限。
- CSV 由服务端同步生成，受时间范围和行数上限保护，使用 UTF-8 BOM 并转义公式前缀。
- 超出同步限制时返回明确的范围错误；不在当前阶段隐式创建异步运行、后台任务或文件对象。

## Compatibility, Rollout and Rollback

- 分析能力保持只读；容量配置通过 additive migration 上线，并允许无历史/未配置状态。
- 新页面与导出入口可独立关闭，既有核心业务不受影响。
- 回滚应用时保留已写入的容量历史和个人保存筛选；不得删除业务事实。
- 未来附件、定时报表和生产性能门禁以独立任务重新复核基础设施、权限和运维条件，不反向扩大本阶段范围。
