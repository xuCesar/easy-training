# P2 运营效率与管理分析

## Goal

完成 GitHub Issue #6 的 P2 阶段：减少跨模块查找、重复录入、线下派单和人工 Excel 汇总，让一线人员在系统内完成高频运营动作，让管理者依据统一、可追溯的经营口径做判断。本父任务维护公共决策、子任务依赖和最终集成验收，不直接承载业务代码。

## Background

- P1 教务、学员/报名和财务闭环已完成；Issue #24–#29、#31、#32 已关闭。Issue #30 是可独立排期的教务体验优化，不阻塞 P2。
- 规划开始时 `develop` 与远端一致且工作区干净；`pnpm check-types` 退出码为 0，`pnpm check` 检查 170 个文件通过。
- 现有系统已有模块内搜索、线索 CSV、学员/报名/班级关系、站内通知、机构审计、财务与课时不可变事实。顶栏全局搜索仍禁用，`operation_task` 只有工作台读取，学员无批量能力，附件无对象存储，经营数据只有实时快照。
- 当前没有后台队列、通用定时执行器、外部邮件/短信/微信渠道或对象存储配置；P2 不隐式依赖 P3 外部触达。

## Requirements

### R1. Delivery Map

- 第一阶段依次交付 T1 全局搜索、T2 运营任务、T3 学员批量操作，先减少查找、派单与重复维护。
- 第二阶段交付 T4 私有附件、T5 核心经营指标、T6 管理对比；必须先固化事实和指标，再建设对比看板。
- 第三阶段交付 T7 保存筛选、导出和定时报表；T7 依赖 T2 调度基础、T4 私有对象存储及 T5/T6 指标查询。
- 每个子任务独立维护迁移、API、权限、审计、并发/幂等、兼容、测试和回滚；父任务最终执行跨任务验收。

### R2. Operational Efficiency

- T1 首期搜索线索、学员/联系人、课程、班级、课次、账单和收款凭证，使用稳定判别联合和类型化站内目标。运营任务、附件在各自交付后接入；成员、通知、审计保持模块内查询。
- 全局搜索与所有深链接均在服务端按机构、角色、校区或教师本人范围裁剪，目标页面再次鉴权；首期复用有上限的 PostgreSQL 查询，不引入搜索引擎。
- T2 支持任务创建、查看、筛选、编辑、分配/认领、完成、重开、改期、重派和取消，并保留版本与不可变状态历史。所有成员可管理本人任务；owner/admin 管理全机构，campus_manager 管理授权校区；其他角色不能给他人派单；公共无负责人任务只由管理角色创建。
- 任务分配时通知，可选一次提前提醒，并在到期及逾期 24 小时各提醒一次；完成时按需通知不同的创建人。改期、重派、完成和取消必须通过任务版本与幂等键使旧提醒失效；公共任务认领前不发送个人提醒。
- T3 学员 CSV 采用创建型、部分成功语义：姓名、校区编码、主要联系人姓名/手机号必填；出生日期、状态、负责人邮箱和已有标签可选。重复手机号或命中现有档案时阻断该行并返回脱敏候选，不自动更新、合并、报名、开单或入班。
- 学员导入的有效行在一个事务中提交并以 requestId 幂等；逐行错误继续返回。负责人、标签、班级批量调整采用预览后整批原子提交，提交时重验权限、状态、版本、课程/校区、班级及教室容量，任一失败则整批回滚。
- 新增可空学员运营负责人和不可变分配历史。候选为有学员校区权限的 owner/admin/campus_manager/consultant；历史学员保持未分配。线索转化默认使用已确认转化归属但可调整，直接报名显式选择；负责人变化不改写销售归属。
- T4 使用 PostgreSQL 元数据加私有 S3 兼容对象存储；本地用 MinIO。对象键由服务端生成，访问用短时授权，不保存公开 URL、数据库二进制或生产本地文件。
- 附件只允许 PDF/JPEG/PNG，最大 10 MiB，并校验扩展名、声明 MIME、实际文件特征、大小和校验值。上传先隔离，生产必须扫描通过后才能预览/下载；无扫描器时生产上传保持关闭。

### R3. Metric Definitions

- 公共时间范围默认上海自然月初至今，并与上月相同已过天数比较；支持 7/30/90 天、本月/季度/年度和最长 2 年自定义。区间左闭右开，快照取结束时点，事件取业务发生时间，cohort 返回成熟度；90 天内按日、超过 90 天按周、超过 1 年按月。
- 招生归属区分线索提供人、当前跟进负责人、首次转化业绩归属人和操作人。提供人与转化归属形成稳定事实，负责人保留历史，操作人只用于审计；首期不支持多人或权重拆分。
- 顾问转化率按所选期间结案周期计算：成功周期数除以成功周期数加流失周期数，按结案时冻结归属，未分配单列；线索流失后重开形成新周期且不覆盖原结果，开放周期只进入在跟数量与实时阶段分布。
- 招生漏斗以所选期间创建线索为 cohort，观察创建后 30 天内真实发生的已联系、已约试听、首次转化和已流失里程碑；允许跳阶段且不补造事实。未满 30 天标记未成熟；提供人获客转化复用同一观察窗。
- 无 `leadId` 的独立报名按直接报名路径保存来源及可选提供人/转化归属，进入总报名和顾问直接报名人数/金额，不进入线索漏斗或顾问线索转化率，也不生成合成线索。
- 主到课率只统计正常班级已完成课次，公式为 `(present + late) / (present + late + absent + leave)`；迟到、请假、缺勤分别展示。取消、未来、未完成和补课不进入主到课率，补课使用独立完成率。
- 消课按不可变 `lessonConsumption` 关联课次的 `lesson.startsAt` 上海业务日期统计，每条实际课消计 1 课时；`consumedAt` 仅用于录入延迟诊断。
- 续费机会在 active 报名剩余课时首次达到最近购买课时数 20%（向上取整且至少 1）时固化；30 个有效观察日内创建续费业务并正式增加课时即成功，不等待账单实际收款，每次续费开启新周期。提前续费、转课单列，冻结暂停观察窗；同时返回续费成交金额、课时和未续费机会。
- 净回款按资金发生时间统计收款减冲正减已批准退款；开单 cohort 回款率为期间开具账单截至观察日的有效净收款除以调整后应收。
- 应收账龄按查询截止日从不可变收款、冲正、退款和账单调整重建有效余额，分为未到期、1–30、31–60、61–90、90 天以上；全额退款账单不形成应收。
- 教师实际利用率为已完成授课分钟/已过去期间有效容量分钟，计划利用率为未取消计划分钟/对应容量分钟。周容量按生效日期保留历史，缺失容量显示未配置；补课学员不重复增加教师时间。
- 班级当前容量利用率为招生中/进行中班级 active 去重学员/容量总和，满班率为达到容量班级/有效班级，90% 至未满为接近满班；历史课次上座率使用发生时应到人数/有效容量。班级容量保留有效期历史，补课不占长期席位但进入课次容量风险。

### R4. Authorization and Reporting

- owner/admin 查看全机构全部指标；campus_manager 查看授权校区完整管理指标；consultant 只看本人招生与脱敏校区基准；finance 只看授权校区财务；teacher 只看本人利用率和本人班级到课。
- 顾问/教师不能看其他成员实名排行；顾问脱敏校区基准至少需要 5 个有效结案周期，否则返回样本不足；未分配归属只向相应管理角色展示。页面、下钻、导出、保存条件和定时报表每次执行均按当前服务端权限裁剪。
- T7 允许保存、重命名和删除本人受控筛选，应用时重新授权；页面和导出复用同一查询、排序、时间范围与指标版本。
- 首期导出 UTF-8 BOM CSV，防公式注入并限制范围/行数；不提供 Excel/PDF。大结果与定时报表使用同一持久运行路径。
- 定时报表只支持每日/每周/每月并按 `Asia/Shanghai` 执行；PostgreSQL 保存计划、下一次执行、数据库租约和运行历史，多实例唯一执行，重启最多补最近一次遗漏。
- 报表文件保存到 T4 私有对象存储 30 天，以站内通知送达；支持停用、恢复和失败手动重试。每次运行固化筛选快照、指标版本、生成时间、结果和失败原因，不支持任意 Cron 或外部发送。

### R5. Engineering Constraints

- 机构、角色和校区均来自服务端当前成员关系；客户端不得指定租户边界。金额使用整数分，业务时间按 `Asia/Shanghai`。
- Zod/oRPC 是公开契约来源；跨表写入使用事务、版本、唯一约束或幂等键；资金、课时、权限、任务和敏感材料动作可追溯。
- 优先复用现有 PostgreSQL、Drizzle、oRPC、TanStack Query、通知、审计和 UI，不为首期引入搜索引擎、数仓、BI、外部队列或第二套组件库。
- UI 必须区分加载、空、错误、无权、未配置和数据未成熟，支持桌面和移动端；不得把失败显示为空数据。
- 每个子任务至少运行相关 PostgreSQL 集成测试、类型检查、Biome 和生产构建；交互改动进行真实浏览器验证。

## Acceptance Criteria

- [x] 已创建并关联覆盖 Issue #6 全部 P2 条目的七个独立子任务，且各自有可验证范围、依赖、非目标和回滚边界。
- [ ] 一线人员可统一查找核心业务记录、完成运营任务、批量维护学员并安全管理材料，关键高频动作无需线下重复登记。
- [ ] 管理者可在许可范围查看招生、教学、续费、财务和资源效率指标及多维对比，口径、事实来源、时区和权限可追溯。
- [ ] 页面、下钻、导出、保存条件和定时报表复用统一服务端查询；权限变化后不会继续暴露旧范围。
- [ ] 调度、对象存储、附件扫描、报表保留和失败重试具备多实例安全、可观察和可停用边界。
- [ ] 七个子任务全部完成并通过各自质量门，P2 经营判断不再依赖人工 Excel 汇总。
