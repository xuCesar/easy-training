# P2 运营效率与管理分析实施计划

## Scope Guard

- 父任务不直接实现业务代码，只维护公共决策、子任务顺序和最终集成验收。
- 每次只启动一个已完成 PRD、设计、实施计划并经用户批准的子任务。
- 不把 Issue #6 的 P3/P4 能力、外部通知、支付、独立数仓或 BI 平台并入 P2。

## Ordered Checklist

1. 完成并归档 T1 全局搜索与跨模块跳转。
2. 规划、实现并归档 T2 运营任务与提醒；确认调度基础可被 T7 复用。
3. 规划、实现并归档 T3 学员批量导入导出与原子批量调整。
4. 规划、实现并归档 T4 私有附件管理与扫描隔离。
5. 规划、实现并归档 T5 核心经营事实和指标口径。
6. 规划、实现并归档 T6 管理对比、应收账龄、回款和资源利用分析。
7. 规划、实现并归档 T7 导出、保存条件和定时报表。
8. 执行跨任务集成核对：权限矩阵、时区、指标版本、搜索扩展、审计、通知和对象生命周期。
9. 同步用户文档、环境变量示例与 Issue #6 交付状态，完成父任务验收。

## Per-Task Quality Gate

- 需求与实现均可映射到该子任务验收标准，无无关重构或未批准范围扩展。
- 数据库变更有兼容、回填、索引、并发和回滚说明，迁移经过审查。
- API 输入输出、服务端授权、错误语义和 Web 状态完整；失败不会伪装为空结果。
- 相关 PostgreSQL 集成测试、类型检查、Biome 和生产构建通过；UI 改动完成桌面与 390px 浏览器验证。
- 子任务归档前记录验证结果、剩余风险和对后续任务提供的稳定契约。

## Final Validation

```bash
pnpm check-types
pnpm test:integration
pnpm check
pnpm build
```

最终还需在真实浏览器按 owner/admin、campus_manager、consultant、finance、teacher 五类视角验证核心路径，并核对权限收回后页面、深链接、导出和已保存计划均不能继续访问旧范围。

## Review Gates and Rollback

- Gate 1：T1–T4 确实减少查找、派单、录入和材料管理的重复劳动。
- Gate 2：T5 的事实与指标口径已被集成测试固化，T6/T7 不存在浏览器侧平行算法。
- Gate 3：跨角色、跨机构、跨校区、未分配和权限收回场景均有服务端证据。
- Gate 4：调度租约、附件隔离、报表文件权限和 30 天清理策略可观测且可停用。
- 任一子任务出现风险时只停用其入口并保留新增数据；不通过删除业务事实回滚。
