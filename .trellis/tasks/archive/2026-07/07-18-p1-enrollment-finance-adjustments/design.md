# P1 技术设计：报名与财务变更

## 数据与不变量

- 新增 `enrollmentStatus`，已有报名默认 `active`；转课来源更新为 `transferred`，后续续费与再次转课均被拒绝。
- `enrollmentRenewal` 保存续费请求、课时增量、账单关联和操作者，以 `(organizationId, requestId)` 唯一约束实现幂等。
- `enrollmentTransfer` 保存来源报名、目标报名、目标课程、转移课时和操作者。来源在同一事务中清空 `remainingLessons` 并解除班级归属；目标报名金额/已收为零，课程差价不在本期自动结算。
- `refund` 是关联账单的不可变资金流水，保存金额、退款时间、方式、原因、操作者和请求 ID。退款金额由流水聚合，不回写或删除 `payment`。
- `invoiceFollowUp` 是账单的追加式人工跟进记录；欠费列表只投影每张账单的最新记录。

## 写入流程

每项写入先以机构 advisory lock 串行化，然后在同一事务内重新读取成员和校区权限、锁定学员/报名/账单，并验证启用状态。

- 续费：锁定报名与学员，检查有效状态和校区，处理相同请求重放，新增续费记录及账单，再原子增加报名的已购与剩余课时。
- 转课：锁定来源报名及其账单，确认无欠费、仍有课时、课程和校区可用；新增目标报名和转课流水，再更新来源状态、余额和班级归属。
- 退费：锁定账单与学员，要求账单已结清；锁定/聚合既有退款后检查上限，新增退款流水。累计退满时将账单设为 `refunded` 并同步报名累计实收。
- 欠费跟进：锁定可访问的未结清账单，新增跟进流水。列表按账单聚合收款/退款并映射最近跟进，避免信任客户端机构或校区。

## API 与 UI

- DB repository 承担事务、机构隔离、锁与错误码；API repository 将记录映射为 Zod 契约并转译为稳定 oRPC 错误。
- 在现有 `training.finance` 下新增 `adjustments`、`refunds`、`arrears` 命名空间，保留已有收款契约兼容。
- `/finance` 继续以账单为主列表：详情抽屉展示退款流水和退款入口；欠费列表提供跟进；报名变更由可搜索的报名选择器启动续费或转课。

## 兼容、回滚与风险

- migration 仅新增表、列、枚举值和索引，既有报名默认 `active`，历史账单不回填退款或跟进。
- 旧应用仍能读取 existing invoice/payment 字段；新版本使用退款流水计算净收。应用回滚不会删除新增历史记录。
- 全额退款会保持 `payment` 不变，但账单不可再收款；这是审计正确性优先于“净额覆盖”的选择。
