# P2 教师与班级资源利用分析

## Goal

交付可追溯的教师标准授课容量、实际/计划利用率、班级容量、满班风险和历史课次上座率，让管理者识别超负荷教师与容量风险。

## Requirements

- 教师资料只配置每周标准授课时长（分钟）和生效日期，不录入具体可用时段，也不从排课反推容量；历史版本不可被当前修改覆盖。
- 实际利用率为已完成授课分钟/有效容量分钟，计划利用率为未取消计划分钟/有效容量分钟；允许超过 100% 并标记超负荷，未配置容量显示不可用而不是 0%。
- 班级容量按生效日期保留历史；当前容量利用率按每班 active 去重学员席位汇总，同一学员跨班分别占位，暂停/结业班级不进入当前分母。
- 达到 90% 但未满为接近满班；历史课次上座率使用课次发生时成员范围与当时班级容量，补课不占长期席位但进入课次实际到场和教室风险。
- 复用 T5 时间/版本/权限 registry；owner/admin 全机构、campus_manager 授权校区、teacher 仅本人利用率和本人班级教学事实，其他角色按父任务矩阵裁剪。
- 上线日前不伪造容量历史；缺失容量、覆盖区间不足和异常超容均返回数据质量计数。

## Acceptance Criteria

- [ ] 教师容量历史按生效区间折算，实际/计划分钟、未配置、部分覆盖与超负荷结果正确。
- [ ] 班级当前席位、满班/接近满班和历史课次上座率按生命周期与容量历史计算且不重复补课。
- [ ] 角色、机构、校区和教师本人范围经服务端测试验证，历史缺口不被当前配置回填伪造。
- [ ] 固定 fixture、迁移/双写、类型检查、Biome、构建和两年范围 explain 通过。

## Dependencies and Out of Scope

- 依赖 T5 指标内核及现有课次、报名生命周期、考勤、教室资源；最终展示由多维经营对比页面子任务完成。
- 不包含具体可授课时段、自动排班、工资绩效、教室优化或预测容量。
