# 实施计划

1. 阅读 db/api/web 相关规范，审查现有审计、线索查询和导出调用链。
2. 扩展 Drizzle schema 和 migration：审计查询字段、通知表、导入批次表及必要索引。
3. 实现 DB repository：通用审计写入与读取、通知收件箱、CSV 预览和幂等导入。
4. 扩展 Zod 契约、授权过程与 oRPC router；在现有导出路径写入审计。
5. 实现 Web 通知菜单、审计页签、线索 CSV 导入流程，并维护查询缓存。
6. 为隔离、幂等、行错误、权限与审计补 PostgreSQL 集成测试。
7. 执行 migration、类型检查、集成测试、check 与生产构建；必要时用现有 3000 服务做浏览器验证。

## 风险点

- CSV 解析需限制文件大小、行数和字段长度，防止同步 API 被大文件阻塞。
- 导入中的负责人/校区引用必须在服务端按机构和成员范围解析。
- 审计快照为 JSONB，需白名单构造，避免带入敏感字段。
