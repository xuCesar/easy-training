# P2 全局搜索与跨模块跳转

## Goal

把当前顶栏的禁用搜索框升级为统一、可键盘操作的业务搜索入口，让成员无需先判断数据属于哪个模块，就能找到有权访问的记录并可靠跳转到对应详情。

## Background

- 线索、学员、账单已有模块内搜索；课程、班级和课次有列表查询；收款凭证可按稳定 ID 读取，但没有跨领域查询契约。
- 顶栏已经预留“全局搜索”输入框，当前为禁用状态；桌面端和移动端均没有可用入口。
- 账单与课次已有受控深链接；线索、学员、课程、班级、收款凭证和教师本人课次仍需补充可刷新、可分享的目标参数。
- 当前 PostgreSQL 与业务规模足以支持带上限的多领域查询；本任务没有引入搜索引擎、全文索引或数据库迁移的证据。

## Requirements

### Search Contract

- 提供机构级 `training.search.global` 只读过程，输入为去除首尾空白后的查询词；长度 2～100 个字符，结果每类最多 5 条，总数最多 35 条。
- 首期结果判别类型固定为 `lead | student | course | classGroup | lesson | invoice | receipt`，每项包含稳定 ID、标题、受控摘要、可空校区/状态信息和类型化站内目标；服务端不返回客户端可篡改的任意 URL。
- 搜索字段覆盖：线索姓名/手机号/来源，学员及联系人姓名/手机号，课程名称/编码，班级名称及关联课程/教师，课次班级/课程/教师/教室，账单摘要/学员/课程，凭证编号/学员/账单摘要。
- 排序优先精确匹配和前缀匹配，再按业务最近时间与稳定 ID 排序；相同输入应有稳定结果。首期不提供模糊拼音、同义词、跨页浏览或全库相关性评分。
- 手机号只用于服务端匹配，结果摘要沿用脱敏格式；财务金额和敏感备注不进入搜索摘要。
- 查询失败返回明确错误状态，不得伪装成“无结果”；不足 2 个字符时前端展示输入提示且不发送请求。

### Authorization Matrix

- owner/admin：可搜索全部七类机构数据。
- campus_manager：可搜索授权校区内的线索、学员、班级、课次、账单和凭证；课程沿用现有教务权限，作为机构级目录可在本机构范围搜索。
- consultant：只搜索其可访问校区内的线索和学员，不返回财务或教务管理目标。
- finance：只搜索授权校区内的账单和收款凭证。
- teacher：只搜索与当前成员显式绑定教师身份相符的本人课次，并跳转到教师工作台。
- 所有裁剪都在 DB/API 返回前完成；直接访问目标 URL 时由目标领域再次鉴权。机构切换后必须关闭搜索并清除旧机构结果。

### Interaction and Navigation

- 桌面顶栏输入框和移动端搜索按钮打开同一个搜索面板；支持 `⌘K`/`Ctrl+K` 打开、`Esc` 关闭、方向键移动、`Enter` 打开结果，并有正确焦点返回。
- 输入采用约 250ms 的延迟查询；面板按结果类型分组，显示加载、输入不足、空结果、错误重试和结果状态。
- 选择结果后关闭面板并通过 TanStack Router 跳转：
  - 线索：`/leads?leadId=...`，加载并定位目标线索。
  - 学员：`/students?studentId=...`，打开学员只读时间线/详情入口。
  - 课程：`/academic?tab=courses&courseId=...`。
  - 班级：`/academic?tab=classes&classGroupId=...`。
  - 课次：管理角色进入 `/academic?tab=lessons&lessonId=...`；teacher 进入 `/teacher?lessonId=...`。
  - 账单：`/finance?invoiceId=...`。
  - 收款凭证：`/finance?invoiceId=...&receiptId=...`，先加载所属账单再打开凭证。
- 深链接必须在当前列表筛选或默认日期范围不包含目标时仍能按 ID 受权加载；不存在、越权或已归档目标要给出可理解提示并清理失效 URL 参数。
- 对课程、班级、课次、线索和学员的定位采用现有页面组件，不创建第二套详情页面；目标关闭后同步移除对应 URL 参数。

### Performance and Observability

- DB repository 对允许的领域执行并行、带上限查询，不先加载全量数据后过滤；所有查询显式包含 `organizationId` 及校区/教师范围。
- 首期复用现有 PostgreSQL `ILIKE`、规范化手机号和领域索引，不新增依赖或 schema。若集成数据或生产慢查询显示单次搜索超出目标，再基于执行计划单独评估 `pg_trgm` 或专用索引。
- 目标为常规测试数据下服务端查询 p95 不高于 500ms；记录聚合耗时、分组数量和失败，不记录原始查询词、完整手机号或结果隐私字段。

## Acceptance Criteria

- [ ] 五类角色均可从桌面和移动入口打开搜索；键盘打开、导航、选择、关闭和焦点返回可用。
- [ ] 七类首期业务对象按角色矩阵返回，跨机构、越权校区、其他顾问/教师或财务数据不会出现在响应中。
- [ ] 姓名、联系人手机号、课程/班级/课次上下文、账单摘要和凭证编号的典型查询可命中，手机号结果保持脱敏。
- [ ] 每类和总量上限、稳定排序、最短输入、加载、空、错误重试状态符合契约，失败不会显示为无结果。
- [ ] 每类结果都能通过可刷新深链接定位目标；目标不在当前筛选/日期范围时仍可打开，不存在或越权时不泄露资源信息。
- [ ] 机构切换不会短暂显示或复用旧机构结果，服务端和目标页面都重新执行授权。
- [ ] PostgreSQL 集成测试覆盖角色矩阵、机构/校区隔离、教师本人课次、结果上限和敏感字段；类型检查、Biome、构建及桌面/390px 浏览器验证通过。

## Dependencies and Out of Scope

- 无数据库迁移和外部基础设施依赖，可作为 P2 第一个实施子任务。
- T2 运营任务和 T4 附件完成后可通过后续小任务接入搜索；本任务首次交付不预留未实现的伪结果。
- 不搜索成员、通知、审计、附件正文或自由文本备注；不提供外部搜索引擎、搜索历史、热门搜索、拼音纠错、跨机构搜索或公开分享链接。
