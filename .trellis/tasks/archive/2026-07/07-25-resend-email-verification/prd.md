# 取消邀请领取的邮箱验证前置条件

## Goal

在暂不集成邮件服务的前提下，让受邀用户使用与邀请一致的邮箱注册或登录后可直接领取机构邀请，不再被 `emailVerified` 阻断。

## Confirmed Facts

- `packages/auth/src/index.ts` 当前只启用邮箱密码认证，未配置 Better Auth 的邮箱验证发送回调，因此无法将用户邮箱标记为已验证。
- `apps/web/src/routes/invite.tsx` 与 `packages/db/src/repositories/organization-management.ts` 均强制要求 `emailVerified`，导致所有新注册的受邀用户无法领取邀请。
- 创建和重发邀请当前只生成 token 并回传给 Web；界面明确提示管理员复制链接后自行发送。
- Resend 邮件投递集成暂时搁置，本次不新增邮件服务、环境变量或依赖。

## Requirements

1. 移除机构邀请领取流程对 `emailVerified` 的前端和服务端强制检查。
2. 保持邀请 token、受邀邮箱匹配、7 天有效期、机构权限校验及领取幂等语义不变。
3. 邀请管理界面继续如实说明当前版本不发送邮件，管理员通过复制链接自行发送。
4. Resend 邮件投递、注册验证、密码重置邮件及相关环境变量不在本次范围内。
5. 邀请列表默认隐藏已撤销记录，并提供“显示已撤销邀请”复选框供管理员按需查看。

## Acceptance Criteria

- [ ] 使用受邀邮箱登录或注册的未验证用户可领取有效邀请。
- [ ] 使用不同邮箱、过期 token、已撤销 token 或已领取 token 时，现有领取失败语义不变。
- [ ] 领取页不再展示“请先验证邮箱”或禁用领取操作。
- [ ] 邀请管理界面仍明确说明当前版本不会发送邮件，并保留复制链接流程。
- [ ] 默认列表不显示 `revokedAt` 非空的邀请；勾选“显示已撤销邀请”后，已撤销邀请与其他邀请一并显示。
- [ ] 受影响包通过类型检查和现有邀请集成测试。

## Product Decisions

- Resend 集成暂时搁置，不引入任何邮件投递实现。
- 当前保留管理员复制邀请链接的兜底流程。
