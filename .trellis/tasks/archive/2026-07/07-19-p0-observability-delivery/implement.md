# P0 可观测性与交付保障：执行计划

1. 服务端：实现请求 ID、结构化访问/异常日志和 `/readyz`，并为新增边界补 Node 测试。
2. CI：新增 PostgreSQL service 工作流，按迁移、检查、测试、构建顺序编排。
3. 文档：补充生产迁移、备份、隔离恢复验证与应用回滚 runbook，标注外部前置条件。
4. 集成：运行服务端测试、Biome、类型检查、集成测试与构建；审查 CI 不含 `db:push` 及敏感配置。

## 风险与验证

- 请求 ID 校验必须防止日志注入；测试应覆盖非法换行值被替换。
- readiness 不得阻塞 liveness；测试数据库错误时只暴露 503。
- CI 迁移命令不得经 Turbo persistent task；以文件静态审查和 workflow 语法检查确认。
- README 仅给出可执行流程，不能断言未提供的生产设施已经启用。
