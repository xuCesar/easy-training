# 实施计划

## 1. 迁移与兼容基线

- [x] 扩展 Drizzle schema：学员负责人和数值版本、负责人分配事件、导入批次、批量操作批次、报名冻结转化归属、生命周期批次关联、审计 action、索引和关系。
- [x] 生成并审查 additive migration；确认历史学员 owner/conversion owner 保持 null、student version 默认 1，不执行启发式回填。
- [x] 更新所有既有学员写路径，使联系人、状态、标签、负责人、合并和新建/报名创建共同维护 `student.version` 与 `updatedAt`；把单条编辑和合并并发契约迁移到 expectedVersion。
- [x] 扩展学员 list/detail 投影与筛选：版本、负责人摘要、具体负责人和未分配；保持旧数据可读。

## 2. 负责人领域与成员权限联动

- [x] 在 DB 层实现负责人候选资格、当前态更新和 append-only 分配事件共享 helper，所有入口复用同一校区/角色校验。
- [x] 扩展线索转化和直接报名契约/UI：冻结可空转化归属；新学员按规则设置 owner；已有学员默认保留 owner，只有管理角色显式动作可同步调整。
- [x] 学员合并预览/提交纳入负责人冲突和显式来源选择，禁止启发式继承。
- [x] 为成员移除、角色/校区范围变更增加负责人影响预览；确认时同事务清空失效 owner、递增版本、追加 `authorization_revoked` 事件并写脱敏审计摘要。

## 3. 学员 CSV 导入与导出

- [x] 抽取/复用 CSV 字节、解析、严格表头、公式防护和 quote helper；定义学员模板列、状态/日期/手机号/标签解析与稳定逐行错误码。
- [x] 实现预览：当前权限下解析校区/负责人/标签，校验文件内手机号重复和同机构全部联系人碰撞，并按可见范围返回脱敏候选或泛化提示。
- [x] 为所有学员创建路径接入排序后的规范化手机号 advisory lock；确认导入在一个事务中重新授权/校验、写所有有效行、固化错误与批次结果，并实现 requestId+inputHash 重放/冲突。
- [x] 实现最多 5000 行、当前筛选/校区裁剪、一学员一行且只含主要联系人的 UTF-8 BOM CSV 导出，统一 quote/公式防护并写脱敏审计。
- [x] 在学员页实现模板下载、导入预览/确认和受限导出；文件变化生成新 requestId，网络重试保留 requestId。

## 4. 负责人和标签原子批量

- [x] 定义最多 200 个显式目标的批量判别联合、预览结果、稳定 blocker code、提交结果和幂等冲突。
- [x] 实现负责人/标签共享 planner：排序锁学员、事务内重验管理角色/校区/版本/目标资格、区分 change/no_change/blocked。
- [x] 实现批次级 requestId+inputHash 幂等和整批原子 apply；实际变化递增 student version，负责人追加事件，中央审计只写一次批次摘要。
- [x] 学员桌面表格和移动紧凑列表增加明确多选、200 项上限和批量动作栏；筛选/翻页不扩大目标，冲突后保留选择并要求重新预览。

## 5. 班级原子批量

- [x] 从 enrollment lifecycle 抽出接收现有 transaction 的共享 plan/apply 内核，保留单条 wrapper 行为和错误映射。
- [x] 统一报名创建、线索转化与生命周期的班级锁顺序和课程/校区/状态/班级容量/未来课次教室容量/重复学员 validator。
- [x] 实现批量班级 planner：按稳定顺序锁资源，以整批最终状态计算重复和容量，返回逐目标 change/no_change/blocked。
- [x] 实现单事务 apply：统一更新 enrollment version、逐目标写 lifecycle event、关联批次，批次重放前置短路，中央审计只写一次。
- [x] UI 通过明确 active enrollment 选择课程报名，提供分配/移出班级预览，不从学员 ID 推断唯一报名。

## 6. 测试与验证

- [x] PostgreSQL 集成测试覆盖 migration 默认值、负责人历史、候选资格、未分配筛选、版本 CAS、成员权限失效自动清空和合并规则。
- [x] 导入覆盖 BOM/UTF-8、引号/换行、严格表头、字节/行数、公式、状态/日期/手机号、文件内重复、同机构任一联系人重复、跨校区隐私、未知/停用/越权引用、部分成功、全无效、系统失败回滚、重放和异载荷冲突。
- [x] 导出覆盖角色/校区裁剪、当前筛选、5000 行上限、一学员一行、只含主要联系人、BOM/quote/公式防护及审计无联系人明文。
- [x] 负责人/标签批量覆盖 change/no-op、200 上限、重复目标、权限/版本/资格变化、整批回滚、重放/冲突、版本递增和单批审计。
- [x] 班级批量覆盖入班/换班/移出、同批腾挪后的最终容量、重复学员、班级/教室容量、课程/校区/状态、报名版本、权限变化、整批回滚、重放和 lifecycle 事实。
- [x] API/应用测试覆盖 consultant 仅可导入、管理角色批量/导出、teacher/finance 拒绝、服务端机构上下文和结构化错误映射。
- [x] 运行 `pnpm db:generate` 并审查 migration，随后执行 `pnpm db:migrate`、`pnpm test:integration`、`pnpm check-types`、`pnpm check`、`pnpm build` 和 `git diff --check`。
- [x] 用真实浏览器验证桌面与 390px：模板/导入错误修复、导出、未分配筛选、多选上限、三类批量预览/提交、并发冲突刷新、权限隐藏和无横向溢出。

## 7. 审查门与回滚点

- [x] 开放批量入口前确认所有既有 student writer 已维护新版本，旧 `updatedAt` CAS 调用方已同步。
- [x] 开放班级批量前确认单条报名/转化/lifecycle 与批量路径共享 validator 和锁顺序，既有集成测试无回归。
- [x] 审查中央审计 JSON 白名单，确认不含 CSV 原文、姓名、手机号、标签自由文本或完整导出内容。
- [x] 若导入/负责人/标签异常，关闭对应 UI/API 新入口并回到维护版本的兼容基线；若班级批量异常，仅关闭班级批量入口，保留单条 lifecycle wrapper。
- [x] 不删除已产生的负责人历史、批次、lifecycle 或审计事实，不回滚到不维护 `student.version` 的旧二进制。
