# P1 补课、班级停复课与教室资源管理

## Goal

让教务能够在系统内完成学员补课、班级停课/复课和校区教室维护，并让新排课、周期排课与未来课次调课统一引用可校验的教室资源；所有操作保留来源事实、权限边界与审计链路。

来源：GitHub Issue #24，父路线图 Issue #6。

## Background

- 系统已有 `course -> classGroup -> lesson` 教学主链，`lesson` 是唯一排课事实。
- 班级已有 `recruiting / running / paused / completed` 状态，但暂停/恢复目前只是普通班级编辑，没有操作原因、未来课次处理或独立审计。
- 已完成、已取消及已经开始的课次代表历史事实，不允许被停复课、调课或补课操作改写。
- 当前单次排课、周期规则和课次都使用 `room` 自由文本；校区只有汇总的 `roomCount` 和 `capacity`，没有独立教室档案。
- 已有教师、教室文本与时间冲突检测，以及周期规则生成、未来课次批量调课、取消和请求幂等基础设施。
- 暂停班级目前不能创建新的单次课次或周期规则，但已有周期规则的生成提交路径尚未统一复核班级是否可排课。

## Requirements

### R1 补课来源与历史保护

- 首期补课采用“学员加入现有未来课次”，不新建专用补课课次，也不改变学员班级归属。
- 来源必须是同机构 active 报名，以及已完成来源课次中该学员的 `absent / leave` 考勤；来源课次、报名、目标课次必须属于同课程、同校区。
- 目标必须是尚未开始的 `scheduled` 课次；补课安排显式关联来源报名、来源课次、目标课次和操作者，来源关系可查询、可审计。
- 创建补课不得修改来源课次、来源考勤或既有课消流水。
- 目标课次点名名单由目标班级 active 报名与有效补课学员共同组成；补课学员不因此转入目标班级。
- 补课学员在目标课次 `present / late` 时正常扣减 1 课时，`absent / leave` 时不扣课并可重新安排。
- 同一来源报名与来源课次同时最多存在一个有效补课安排；人工取消、目标课次取消或再次缺勤/请假后允许重新安排。
- 重复或并发请求不得生成重复补课课次，也不得产生重复课消。
- 首期一次安排一个补课学员；持久化边界应允许后续扩展专用补课课次和同一目标课次的多个补课学员。

### R2 班级停课与复课

- 仅允许具有教务写权限且拥有目标校区权限的成员操作。
- 停课和复课必须填写原因，并记录操作人、操作时间、班级、校区和处理结果。
- 停课后禁止新的单次排课、周期规则创建及已有周期规则继续生成新课次。
- 已完成、已取消及已经开始的课次保持不变。
- 停课时必须在以下两种未来课次处理方式中显式选择：
  - 保留未来课次：尚未开始的 `scheduled` 课次保持不变，但班级暂停期间不能点名、结课或调课；必须先复课才能继续处理。
  - 取消未来课次：填写统一取消原因，在停课事务中原子取消提交时仍未开始的 `scheduled` 课次。
- 周期规则定义在停课时保留，不删除、不修改有效期；班级暂停状态统一阻止规则创建、更新、生成、同步和调课。
- 选择保留的未来课次若在仍未复课时到达开始时间，作为待人工处理异常展示，不能静默结课或改写。
- 复课只恢复班级的可排课状态，不自动重建此前取消或缺失的课次。

### R3 教室资源

- 在机构和校区边界内维护教室名称、容量和启停状态。
- 教室名称在同一校区内不可重复；停用教室不能用于新的排课、规则创建或未来课次调课。
- 教室存在尚未开始的 `scheduled` 课次时，停用操作必须阻止提交，并返回受影响课次列表；教务需先调课或取消相关课次。
- `owner / admin` 可维护机构内教室，`campus_manager` 只能维护其授权校区的教室。
- 教室写操作必须由服务端重新校验机构、角色和校区权限，并记录审计。
- 历史课次原有 `room` 文本必须继续正常展示和查询。

### R4 排课、调课与容量

- 新的单次排课、周期规则、周期课次生成和未来课次调课统一引用启用中的教室资源。
- 提交前继续校验教师、教室和时间冲突；服务端提交时必须再次校验。
- 新排课、周期排课、未来课次调课和补课目标选择必须满足：目标班级 active 学员数与该课次有效补课人数之和不超过教室容量；不满足时服务端硬阻断。
- 后续入班必须检查目标班级全部未来待上课次；若新增学员会导致任一已关联教室的未来课次超容，则阻止入班并返回受影响课次与教室。
- 首期不允许人工绕过容量限制；后续可扩展带专门权限和审计的例外审批。
- 已完成、已取消、已经开始或仅保留历史教室文本的课次不追溯阻断，只展示容量未知或历史超容提示。
- 历史自由文本教室不要求强制回填为教室资源。

### R5 一致性、幂等与可审计

- 补课创建、班级停复课及涉及未来课次/周期规则的批量动作使用事务保护。
- 可能由网络重试重复提交的动作使用机构内幂等请求标识，并校验请求内容指纹。
- 所有关键写操作记录机构审计，不记录学员敏感备注或完整考勤名单。

## Acceptance Criteria

- [ ] 能将来源课次中 `absent / leave` 的 active 报名学员安排到同课程、同校区的未来待上课次；重复/并发请求只产生一条有效安排。
- [ ] 目标点名名单包含补课学员但不改变其班级归属；目标 `present / late` 恰好扣减一次课时，`absent / leave` 不扣课并允许重排。
- [ ] 补课安排、取消、重排和完成均不改写来源课次、来源考勤或来源课消。
- [ ] 班级停课/复课有明确原因与审计；停课提交必须选择保留或取消未来课次，历史冻结课次不受影响。
- [ ] 选择取消时，班级状态和所有符合条件的未来课次在同一事务更新；选择保留时不改写课次。
- [ ] 暂停班级无法通过单次排课、规则创建或已有规则生成路径产生新课次。
- [ ] 暂停班级不能点名、结课或调课；保留课次到期未复课时有明确异常提示。
- [ ] 复课不会自动重建已取消或缺失课次，也不会自动生成规则课次，教务可重新预览和排课。
- [ ] 可按校区创建、编辑、启用和停用教室，并校验同校区名称唯一与容量合法。
- [ ] 停用教室不能用于新排课或调课，引用该教室的历史课次仍正常展示。
- [ ] 存在未来待上课次时停用教室被阻止，并返回受影响课次；仅历史课次引用时允许停用。
- [ ] 新排课、调课和补课使用教室资源，并继续执行教师、教室、时间和容量硬校验。
- [ ] 新增学员不会使目标班级已有未来课次超过教室容量；容量不足时返回明确的受影响课次与教室信息。
- [ ] PostgreSQL 集成测试覆盖权限、事务、幂等、并发、历史兼容和主要错误分支。
- [ ] 相关类型检查、规范检查、桌面端与移动端关键交互验证通过。

## Out of Scope

- 自动排课优化。
- 跨校区共享教室。
- 教室设备、租赁、分区或组合教室管理。
- 教师薪酬、请假审批和家校通知。
- 自动为暂停期间补齐或顺延整套课程计划。

## Resolved Decisions

- 教室存在未来待上课次时阻止停用；已完成、已取消或已开始课次不阻止停用。
