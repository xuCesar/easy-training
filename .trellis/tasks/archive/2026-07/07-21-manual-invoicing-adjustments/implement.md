# 实施计划：通用手工开单与账单调整

## 顺序清单

1. 先补充财务与审计规范中的手工开单、来源隔离、调整状态矩阵、审计白名单和幂等/版本契约，确保后续实现有稳定边界。
2. 扩展 Drizzle schema：账单来源/活动类型/摘要/创建人/版本，新增手工开单幂等事实、账单调整事实和两个审计 action；生成 migration，逐句审查历史回填、非空转换、索引和 enum SQL。
3. 更新所有自动开单写入点，显式写报名/续费来源、活动类型、摘要与操作人；统一报名已收重算过滤，排除 manual 来源账单。
4. 在 DB finance repository 实现财务专用学员/报名选项、手工开单、账单调整、详情历史与能力投影：事务内重授权、机构/校区隔离、行锁、输入指纹、并发重放、版本比较和同事务审计。
5. 扩展 Zod contracts、API repository 和 oRPC router，提供稳定来源/类型字段、创建/调整结果、结构化能力与错误映射；不得扩大 finance 角色对学员管理接口的权限。
6. 先扩展 PostgreSQL 集成测试并修正实现：覆盖角色/撤权、租户/校区、停用校区、报名关联状态、幂等载荷、并发创建、版本冲突、调整与收款竞态、状态冻结、事务回滚、审计数量和报名金额隔离。
7. 实现 Web 手工开单 Dialog、列表来源/摘要、详情元数据与调整历史、账单调整 Dialog；复用现有 UI 和查询失效模式，覆盖加载、空态、字段错误、重试、提交中、成功后打开详情及版本冲突保留输入。
8. 同步审计页 action 标签、Dashboard 与学员时间线的手工账单文案/摘要，确保无报名账单不再显示“课程待确认”或“未命名课程”。
9. 执行迁移、类型、集成测试、Biome、构建和差异检查；启动现有开发服务完成桌面与 390px 移动端的开单、调整、收款及异常状态浏览器验证。

## PostgreSQL 集成测试矩阵

- 创建：四种财务角色成功；consultant/teacher、事务前撤权、跨机构/校区、无校区权限和停用校区拒绝。
- 关联：无报名可创建；同学员 active/frozen 可关联；transferred、其他学员或其他机构报名拒绝。
- 类型与输入：四种手工活动类型、摘要/原因长度、金额边界、日期和服务端固定 manual 来源。
- 幂等：相同 requestId/相同完整载荷串行和并发均返回同一结果；任一关键字段不同均冲突；账单、creation、adjustment 和审计数量准确。
- 调整：未收款三字段分别/组合调整；空变更拒绝；部分收款只允许日期/摘要；历史 paidAmount 无 payment、已结清、已退款均执行冻结规则。
- 并发：陈旧 expectedVersion 拒绝；两个调整只成功一个；调整和收款竞争后无超收、无收款后金额改写、无丢失更新。
- 聚合：手工账单进入列表、详情、欠费和 Dashboard；关联报名后收款不改变 enrollment 课程已收，自动报名/续费账单仍正常更新。
- 审计与回滚：成功恰一条 action，replay 不新增，失败零审计；审计插入或外键失败时领域事实和版本全部回滚；中央审计不含自由文本原因、摘要或敏感资料。
- 兼容：历史报名/续费/无报名账单来源回填正确，旧 paid 状态兼容映射、时间 ISO 和金额整数契约保持稳定。

## Review Gates

- 不允许手工账单收款进入报名课程已收聚合，不允许通过关联报名静默改变课程金额或课时。
- 不允许只依赖 API middleware 权限、客户端 capabilities 或前端禁用状态；创建和调整必须在 transaction 内重读授权与资源。
- 不允许通过覆盖 payment/refund、直接更新 invoice 而不写 adjustment，或把 requestId 仅存入审计 JSON 实现本功能。
- 调整与收款必须锁同一 invoice 行；金额冻结同时检查 paidAmount、存储状态和资金流水，兼容历史数据。
- 所有新增 enum、审计 action、API schema、Web 标签和 Trellis 规范必须同步。
- migration 必须可在包含零价、历史 paid 快照和无 enrollment 账单的现有数据上安全执行。
