# 学员业务时间线执行计划

## 实施顺序

1. 扩展 Drizzle schema、生成并审查仅新增的迁移与快照：`student_status_event` 及其查询索引。
2. 在学员 repository 的现有事务中写入真实状态变更事件；补 DB timeline repository，统一聚合、角色/校区裁剪及游标排序。
3. 扩展 Zod 契约、API adapter 和 `training.students.timeline` Router；确保输出中不含隐藏财务数据、联系人、退款原因或支付参考号。
4. 补 PostgreSQL 集成测试：跨来源排序和分页、同时间稳定性、状态事件、旧学员兼容、机构/校区/角色隔离，以及财务事件不向顾问泄露。
5. 为财务账单与教务课次补 URL 定位能力，并在目标页面沿用现有鉴权与加载/错误状态。
6. 在学员中心实现时间线面板与深链接，覆盖加载、空、错误、更多与窄屏交互。
7. 更新相关 Trellis 规范，执行全量检查与浏览器验证。

## 关键风险与防护

- 多来源分页：游标必须包含时间、事件种类排序键、来源 ID；集成测试覆盖相同时间的跨页边界。
- 权限：只在服务端决定事件集合与导航目标；前端隐藏不作为安全边界。
- 历史事实：不回填学生状态；所有现有资金、课时、报名和考勤记录只读。
- 路由定位：无权、已删除或不在当前校区范围的目标以既有空/错误状态显示，不能泄露存在性。

## 验证

```bash
pnpm db:migrate
pnpm check-types
pnpm test:integration
pnpm check
pnpm build
git diff --check
```

另用浏览器检查：学员时间线的空/加载/失败/加载更多、财务和课次深链接、移动端布局，以及受限角色不可见财务事件。
