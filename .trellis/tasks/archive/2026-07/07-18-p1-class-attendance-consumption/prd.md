# P1 学员入班、考勤与课时消耗基础能力

## Goal

基于既有报名、班级和课次，形成可追溯的入班、点名和课时消耗闭环。运营人员能够为已报名学员调整班级归属，为已排课课次登记考勤，并在结课时安全扣减课时。

## Confirmed Facts

- `enrollment.classGroupId` 已表达报名与班级的归属，线索转报名已校验课程、校区、容量和重复入班。
- `attendance` 已有 `lessonId + studentId` 唯一约束，支持 `present/absent/late/leave` 与备注，但没有业务 API 或 UI。
- `remainingLessons` 保存在 `enrollment`，现有系统没有课时消耗流水，不能以重复更新余额的方式实现幂等。
- `lesson` 是唯一排程事实；`cancelled` 不应被点名或结课，`completed` 需要成为结算完成的不可逆状态。

## Requirements

### R1 入班归属

- 教务人员可为当前机构、可访问校区的报名选择同课程、同校区且 `recruiting/running` 的班级，或取消班级归属。
- 入班校验容量、课程、校区、机构与重复学生归属；不修改报名金额、购买课次或剩余课时。

### R2 考勤与结课

- 仅可对 `scheduled` 课次的当前班级成员登记考勤；同一学员同一课次仅保留一条考勤记录。
- 结课操作以一份完整点名名单完成：将课次切换为 `completed`、写入考勤，并对 `present/late` 学员执行一次消课；`absent/leave` 不消课。
- 已完成或已取消课次不可重复登记、结课或取消，避免历史考勤和课时流水被改写。

### R3 课时消耗与审计

- 每条消耗记录唯一关联一个 `enrollment + lesson`，记录扣减前后课时、考勤状态、操作者和时间。
- 消课与考勤、课次状态及 `remainingLessons` 更新同一事务完成；剩余课时不足时整笔结课失败，不产生部分写入。
- 所有读写重新校验当前成员角色、机构和校区范围。

### R4 界面

- 班级列表提供成员数量与入班管理入口；课次列表提供点名与结课入口，并展示结课状态。
- 点名界面覆盖加载、空、错误、提交中与移动端布局；错误消息清楚说明不可结课原因。

## Acceptance Criteria

- [ ] 授权成员可在同课程、同校区、未满班级间调整报名归属；越权、跨机构、跨课程、停用校区和重复归属被服务端拒绝。
- [ ] 仅可为已排课课次的班级成员登记考勤；取消、完成课次和非成员均不能写入。
- [ ] 结课一次性持久化考勤与课时消耗；到课/迟到扣 1 课时，缺勤/请假不扣，剩余课时不会为负。
- [ ] 重复或并发结课只产生一份消耗流水，且不会重复扣减余额。
- [ ] PostgreSQL 集成测试覆盖机构隔离、校区权限、容量、课时不足、幂等与并发；前端覆盖核心正常和错误状态。

## Out Of Scope

- 请假审批、补课、调课、代课、批量历史导入、退款、课时回滚和教师薪酬。
- 复杂的多课程合并扣课、试听课、赠课、跨班共享报名与自动排课。

## Notes

- 本期采用“登记考勤并结课”作为结算动作，避免在可反复编辑的考勤草稿期间扣减课时。
