# P1 学员档案、家长联系人与标签

## Goal

建立受机构与校区范围保护的学员主档案。招生顾问和校区运营人员可以在不改变报名、账单与课时语义的前提下，维护学员生命周期状态、多个家长联系人及运营标签，为后续班级、排课与考勤提供稳定的 `studentId` 边界。

## Confirmed Facts

- 当前 `student` 已关联机构和必填校区，保存姓名、出生日期、单个 `guardian_name` / `guardian_phone` 与 `active`、`trial`、`paused`、`graduated`、`at_risk` 状态。
- 生产环境仅通过线索转报名创建或匹配学员；手机号匹配依赖现有 `student.guardian_phone`。
- 多校区权限已由服务端 `CampusAccess` 强制，停用校区历史可读但业务写入必须拒绝。
- Web 中的“学员中心”仍为占位，当前没有独立学员 API、列表、详情或维护流程。
- `course.tags` 不能复用为学员标签，当前不存在学员标签领域模型。

## Requirements

### R1 学员档案

- 授权角色可在自身校区范围内分页查看、搜索、新建、查看详情和编辑学员。
- 列表支持按校区、状态、标签筛选，按学员姓名、主要联系人姓名或手机号搜索。
- 学员基础字段为姓名、所属校区、可选出生日期和现有状态枚举；本期不新增状态或自动流转规则。
- 学员校区在本期创建后不可直接迁移，避免与既有报名、账单和后续班级归属产生不一致；跨校区转档作为后续独立流程。

### R2 家长联系人

- 每位学员拥有一个或多个联系人，每个联系人包含姓名、手机号、可选关系称谓及是否为主要联系人。
- 任意时刻必须至少有一位且仅有一位主要联系人；创建学员时必须提交主要联系人。
- 主要联系人与现有 `guardian_name`、`guardian_phone` 同事务保持一致，确保线索转报名的既有手机号匹配不回归。
- 联系人手机号仅向有学员档案权限的角色在详情中展示完整值；列表仅返回脱敏值，审计、错误与日志不得泄露完整手机号。

### R3 机构级标签

- 标签归属机构，名称规范化后在机构内唯一；可启用、重命名与停用。
- `owner`、`admin` 管理标签字典；具有学员编辑权限的角色只能为自己可访问的学员分配启用标签。
- 停用标签仍显示于既有学员档案，但不允许继续赋予新学员。
- 同一标签不能在同一学员上重复绑定。

### R4 权限与生命周期边界

- `owner`、`admin`、`campus_manager`、`consultant` 可访问本机构且自身校区范围内的学员档案；`teacher`、`finance` 本期无学员中心权限。
- 服务端在列表、详情和每一次写事务中重新验证机构、校区范围和校区启用状态；客户端筛选参数不能扩大范围。
- 停用校区的历史档案仍可查看，但不可新建或修改学员、联系人、状态、标签关联。
- 状态仅表示人工维护的运营状态，不自动修改报名、账单、收款、课时或排课数据；本期不提供物理删除、合并、批量编辑和自动标签。

## Acceptance Criteria

- [ ] 授权角色可在可访问且启用的校区创建学员，姓名、校区和主要联系人姓名/手机号校验明确。
- [ ] 学员列表可按校区、状态、标签筛选，并按姓名、主要联系人姓名或手机号查询；受限成员不能取得范围外数据。
- [ ] 学员详情可维护出生日期、状态、多个联系人和标签，任意时刻恰有一位主要联系人。
- [ ] 现有学员均从原监护人字段获得主要联系人；线索转报名的新学员也会创建对应联系人，手机号匹配行为保持正确。
- [ ] 标签在机构内唯一；停用标签保留历史展示但不能再次分配；只有 owner/admin 可管理标签字典。
- [ ] 停用校区可读取历史学员，但任何档案写入都被服务端拒绝；teacher/finance 无法取得联系人、出生日期或标签。
- [ ] 状态变更不修改报名、账单、收款或课时记录；学员不提供物理删除入口。
- [ ] 关键机构隔离、校区范围、停用校区、主要联系人不变量和转报名兼容路径有集成测试。

## Out Of Scope

- 家长登录、家校沟通、通知、健康档案、住址、证件、附件和敏感备注。
- 家庭主档案、兄弟姐妹关联、跨学员共享联系人和联系人去重。
- 自动状态流转、标签规则、批量编辑、导入导出、学员合并和跨校区转档。
- 课程、班级、排课、考勤、课消的创建或改造。
