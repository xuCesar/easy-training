# P1 实施计划：课程、班级与课次排程

## Execution Order

1. 审查现有 schema 与 migration，追加课程启用、课次取消审计及必要索引。
2. 新增 DB 教学 repository：课程、教师、班级和课次的列表/详情/写入；抽取并复用事务内成员授权刷新与校区校验。
3. 实现课次冲突、班级容量和状态转换校验，并同步报名转化候选的课程启用兼容。
4. 扩展 API contracts、领域 procedures、router 与错误映射；禁止客户端传入机构边界。
5. 新增教务路由与高密度运营 UI：课程、教师、班级、课次列表和表单，激活侧栏入口。
6. 补 PostgreSQL 集成测试、浏览器桌面/移动端验收与独立安全审查。

## Validation

```bash
pnpm db:migrate
pnpm check-types
pnpm test:integration
pnpm check
pnpm build
```

关键浏览器路径：创建课程与教师 -> 开班 -> 创建正常课次 -> 拒绝教师/教室冲突 -> 取消课次 -> 报名转化仍只显示可报名班级。

## Review Gates

- migration 确认不修改历史报名、班级、课次语义。
- 事务冲突测试包含相邻时间、已取消课次、同教师、同校区同教室及并发提交。
- 权限测试包含跨机构、权限撤销后写入、停用校区、teacherCampus 缺失和课程停用。
- UI 审查确认 `scheduleText` 没有成为第二套可编辑排程来源。

## Risks

- 课程停用和班级状态直接影响报名转化候选，必须对现有集成测试补兼容断言。
- 普通范围查询不足以抵抗并发排课，冲突检测和插入必须由同一事务保护，并将锁冲突转换为明确业务失败。
- 教师档案是班级创建的前置资源；不能用硬编码或开发种子数据代替正式维护入口。
