# 欠费处理工作流

## Goal

为每轮真实待收建立明确状态、操作历史和校区权限边界，使财务人员能持续跟进且不会将人工状态与资金事实混为一谈。

## Background

- 当前欠费为非 `refunded` 且 `amountInCents > paidAmountInCents` 的账单，列表按到期日排序。
- 当前 `invoiceFollowUp` 仅保存追加备注，列表只展示最新一条，没有状态、版本或欠费轮次。
- 已结清或全额退款账单不能继续新增跟进。

## Requirements

- 每轮欠费具有独立周期，当前状态为“待跟进 / 跟进中 / 承诺付款 / 暂停追缴 / 已解决”，枚举与展示映射保留扩展边界。
- 新账单首次产生待收时自动创建周期并进入“待跟进”；`跟进中`、`承诺付款`、`暂停追缴` 由授权用户人工选择。
- 未收金额归零时在资金事务内自动进入“已解决”，未结清账单不能人工设置“已解决”。
- 已解决后因冲正或其他受支持资金操作重新产生待收时创建新周期并进入“待跟进”；旧周期与历史完整保留，不恢复旧状态。
- “承诺付款”要求承诺日期必填且不得早于操作当天，备注可选；“暂停追缴”要求暂停原因必填、恢复日期可选；“跟进中”无额外必填字段。
- 每次人工或自动变化保存周期、前后状态、事件类型、操作人/系统来源、时间、请求标识及对应的承诺日期、恢复日期、原因或备注；历史不可修改。
- 人工操作必须锁定账单与当前周期，在事务内重新授权并使用预期版本防止覆盖并发更新。
- 欠费列表只返回授权校区的真实待收账单，支持按当前状态筛选，并能发现没有恢复日期的长期“暂停追缴”。
- 现有 `invoiceFollowUp` 备注必须迁移或兼容到首轮周期历史，不得丢失操作者、时间和内容。
- 新建账单、收款结清和冲正重新欠费必须在各自原业务事务中同步维护周期，不能依赖前端或异步任务最终修正。
- 自由文本备注和原因不复制到中央审计；中央审计只记录周期、账单、状态变化、操作者、时间和校区。

## Acceptance Criteria

- [ ] 财务四角色可按校区查看和筛选当前欠费，进入单据查看全部轮次与事件历史。
- [ ] 状态专属字段按规则校验；未结清不能标记“已解决”，长期暂停记录可筛选发现。
- [ ] 收款使未收归零时自动解决；冲正重新产生待收时创建新周期且不覆盖上一轮。
- [ ] 越权、跨机构/校区、停用校区、过期版本和并发状态变更被拒绝且不产生部分历史。
- [ ] 迁移后现有跟进备注数量、操作者、时间和内容仍可追溯。
- [ ] 账单金额、欠费列表、当前状态与历史轮次在失败回滚和并发资金操作下保持一致。

## Dependencies and Out of Scope

- 依赖 `07-21-payment-reversals` 提供“结清后重新产生待收”的资金路径。
- 不提供自动短信/微信催缴、外部催收、催收评分、定时自动解除暂停或自动执行承诺付款。
