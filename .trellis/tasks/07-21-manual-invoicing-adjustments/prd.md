# 通用手工开单与账单调整

## Goal

在现有应收账单与收款闭环上，补充可追溯、可控且具备并发保护的手工开单与账单调整能力，使机构能够处理材料费、考试费、补差价等非报名套餐收费，同时不改写既有收款事实。

关联 GitHub Issue：[#28](https://github.com/xuCesar/easy-training/issues/28)

## Users and permissions

- `owner`、`admin`、`campus_manager`、`finance` 沿用现有财务权限，可创建手工账单和执行允许的调整。
- `campus_manager` 和受限校区成员只能操作其授权校区中的学员、报名与账单。
- 所有写入在数据库事务内重新读取有效机构成员、角色、校区范围和校区启用状态；不得仅依赖 API middleware 的授权快照。

## Requirements

### 手工开单

- 手工账单必须关联当前机构、当前授权校区内的学员；可选关联该学员在同机构内的报名。
- 若关联报名，报名必须属于所选学员，且其课程与校区关系有效；不允许通过客户端输入跨机构或跨学员关联。
- 在读或冻结报名允许作为追溯关联；已转出报名不允许承接新账单。历史事项如需收费，创建仅关联学员的手工账单并在摘要说明原课程。
- 开单记录业务来源、业务活动类型、摘要、金额、到期日、操作人、创建时间和请求标识。
- 账单来源由系统确定为报名、续费或手工，不能由客户端任意指定；API 以稳定字段返回来源。
- 手工账单首版业务活动类型固定为材料费、考试费、补差价、其他；类型使用可扩展的领域枚举/映射，后续增加活动费等类型时不改变账单来源、收款或聚合模型。
- 手工账单摘要必填；选择“其他”时通过摘要明确具体收费事项，不额外引入自由文本类型字段。
- 金额使用整数分，必须大于 0 且不超过现有账单上限；到期日使用上海业务自然日。
- 手工账单进入现有账单列表、详情、欠费聚合和收款流程，状态、逾期与未收金额继续使用统一计算规则。
- 相同机构内相同 `requestId` 与相同完整载荷重放时返回原结果；相同 `requestId` 携带不同载荷时拒绝，不重复创建账单或审计。

### 来源兼容

- API 和 UI 必须能区分自动报名账单、续费账单与手工账单。
- 既有账单需要兼容回填或稳定推导来源，不因新增字段而丢失列表、详情、欠费、时间线或收款能力。
- 手工账单未关联报名时，课程名称为空；列表和详情应优先显示账单摘要及明确来源，不继续使用“课程待确认”造成误解。
- 手工账单的可选报名关联仅用于业务追溯和展示，不改变报名的课程套餐金额、累计已收金额、购买课时或剩余课时。
- 手工账单无论是否关联报名，都独立进入机构总应收、欠费与收款统计；报名层累计已收仅聚合报名和续费来源账单，排除手工来源。
- 课程续费继续使用现有续费入口，以保证新增课程应收与课时同步；手工“补差价”不静默改写原报名合同金额。

### 账单调整

- 调整采用追加式不可变流水，保存原因、操作人、创建时间、请求标识、调整前后关键值与目标账单版本。
- 未产生任何收款的待收账单支持受控调整金额、到期日和摘要；金额调整后的总额必须大于 0。
- 已部分收款后金额永久冻结，仍允许调整剩余欠款的到期日和账单摘要；调整必须保留原因与关键前后值。
- 已结清或已退款账单的金额、到期日和摘要全部冻结，不再通过本功能调整。
- “已产生收款”同时以 `paidAmountInCents > 0` 和既有资金流水判断，兼容没有完整 payment 明细的历史账单，不允许通过缺失流水绕过金额冻结。
- 涉及已有收款金额的冲正或资金差异处理由后续 Issue #29 承担，不能通过账单调整改写。
- 调整成功时更新账单当前投影并递增版本；陈旧 `expectedVersion` 必须拒绝，不能覆盖并发修改。
- 同一调整请求幂等重放不重复更新版本、不重复新增调整流水或审计；同一请求标识的不同载荷冲突。
- 调整失败时账单、调整流水和审计全部回滚，不允许部分成功。

### 审计与隐私

- 手工开单和账单调整均在同一 PostgreSQL transaction 中写机构审计，并记录账单所属校区。
- 审计使用新增且可筛选的明确 action；账单调整审计包含业务字段的关键前后值和 `requestId`。
- 详细调整原因保存在调整流水中；机构审计不复制自由文本原因、学员联系方式或其他敏感信息。
- 收款、退款及历史账单流水保持不可变，不能通过调整删除或重写。

### UI and interaction

- 财务工作台提供明确的“手工开单”入口；桌面端使用与现有财务页一致的表单/弹层模式，移动端保持全宽可操作。
- 学员选择必须提供加载、搜索、空状态和错误状态；报名为可选项，并随所选学员联动过滤。
- 账单详情展示来源、业务类型、摘要、创建人/创建时间、当前版本以及按时间倒序的调整历史。
- 仅在当前账单状态允许时显示调整入口；提交中阻止重复提交，失败保留输入并提供明确错误提示。
- 创建或调整成功后刷新账单列表、详情、欠费聚合、工作台快照及相关学员业务时间线查询。

## Constraints / Out of scope

- 本期不引入会计科目、税务发票、在线支付、复杂折扣引擎或审批流。
- 本期不实现收款冲正；已产生收款后的资金差异由 Issue #29 的追加式调整/冲正流程承担。
- 不新增无必要依赖，不建立与现有 `invoice`、`payment`、机构审计并行的第二套财务模型。

## Acceptance Criteria

- [ ] 授权用户可为可访问校区内的学员创建手工账单，可选绑定该学员报名；手工账单可在既有列表、详情、欠费和收款流程中正常使用。
- [ ] 可选报名只返回并接受所选学员的在读或冻结报名；已转出、跨学员、跨机构报名均不能关联。
- [ ] API 可稳定区分报名账单、续费账单与手工账单，既有数据兼容且列表/详情不会用含糊占位文案掩盖手工账单来源。
- [ ] 关联报名的手工账单可追溯到课程，但其创建、收款和调整均不改变报名课程金额、报名累计已收或课时。
- [ ] 未收款账单可调整金额、到期日和摘要；部分收款后仅可调整到期日和摘要；已结清或已退款后全部冻结。
- [ ] 已收款金额和收款流水不会被直接改写；不允许的调整返回明确业务冲突。
- [ ] 越权、跨机构、跨校区、跨学员报名关联、停用校区、陈旧版本和幂等载荷冲突均被服务端拒绝。
- [ ] 相同创建/调整请求重放只产生一份领域结果和一条审计；并发写入不会重复开单或丢失调整。
- [ ] 任一步骤失败时账单、调整流水、版本与审计均不产生部分数据。
- [ ] PostgreSQL 集成测试覆盖成功、重放、并发、权限/租户、状态边界、旧数据兼容和事务回滚；API 契约覆盖字段序列化及错误映射。
- [ ] 相关类型检查、Biome 检查、构建通过，并完成财务工作台桌面端与移动端的实际交互验证。

## Confirmed product decisions

- 首版手工业务活动类型为材料费、考试费、补差价和其他，并保留可扩展的领域枚举/映射边界。
- 部分收款后金额冻结，但到期日和摘要仍可受控调整；结清或退款后全部冻结。
- 手工账单的报名关联只用于追溯，不计入课程套餐金额、报名累计已收或课时。
- 在读和冻结报名可关联；已转出报名不可关联。
