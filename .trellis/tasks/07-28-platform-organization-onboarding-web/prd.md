# 平台机构负责人初始化 Web 管理

## Goal

为试运行期的平台运维人员提供受控的 Web 管理入口，用于创建、查看、重新生成和撤销“新机构开通邀请”。受邀用户继续通过现有 onboarding 流程注册，系统自动创建指定机构并授予该用户 `owner`，从而替代日常 SSH + SQL 脚本操作，降低误操作成本并补齐平台级可追溯性。

## Background / Confirmed Facts

- 生产环境默认关闭公开注册；新机构只能通过平台签发且绑定目标邮箱的 onboarding token 开通。
- 现有受邀人流程已完成：`/onboard#token=...` 将 token 放入 sessionStorage 并从地址栏移除，随后注册请求通过 `X-Onboarding-Token` 发送（`apps/web/src/routes/onboard.tsx:13-35`）。
- 数据库只保存 SHA-256 token hash；明文 token 仅在创建或重新生成时返回一次。同邮箱创建新有效邀请前会撤销旧有效邀请，默认有效期 7 天（`packages/db/src/repositories/organization-onboarding.ts:10-69`）。
- 有效邀请在机构初始化事务中被锁定并领取；同一事务创建机构、授予受邀用户 `owner`、标记邀请已领取并写入机构审计（`packages/db/src/repositories/organization.ts:319-377`）。
- 当前邀请表不隶属任何机构，包含目标邮箱、机构名称、备注、到期/撤销/领取状态以及领取后创建的用户和机构，但没有创建/撤销操作员字段或独立平台审计事件（`packages/db/src/schema/training/organization.ts:151-183`）。
- 当前生产操作依赖 `/home/ops/create-onboarding-link.sh`，脚本直接写数据库并把非 token 操作摘要追加到 `/home/ops/onboarding.log`（`ops/onboarding/create-onboarding-link.sh:1-49`）。
- 当前权限模型只有机构级成员角色；仓库中没有独立的平台管理员/平台操作员模型。机构 `owner/admin` 不应因此获得创建其他机构的权限。
- 当前注册前置闸门校验邮箱 + token，但最终领取事务只按邮箱锁定有效邀请；若前置校验与领取之间发生重新生成，旧 token 存在错误领取新邀请的竞态风险（`packages/db/src/repositories/organization-onboarding.ts:76-106`）。Web 管理入口开放前必须修正该不变量。

## Requirements

### R1. 平台授权边界

- MVP 使用仅服务端可见的邮箱白名单识别平台操作员；必须同时要求有效登录 session 与已验证邮箱。
- 平台授权与机构角色分离，不允许仅凭当前机构 `owner/admin` 调用平台 onboarding API。
- Web 入口是否展示只能改善体验，所有读写授权必须由服务端过程强制执行。
- 设计必须保留向独立平台操作员权限模型迁移的清晰边界，不能把白名单判断散落在页面、router 和 repository 中。
- 平台授权应通过稳定的 capability/provider 抽象执行；白名单为空时必须 fail closed，后续切换数据库操作员模型时采用显式授权模式，避免白名单与数据库权限长期隐式并集。

### R2. Web 管理能力

- 提供独立的 `/platform/onboarding` 平台 onboarding 管理页面，不放入普通机构设置或机构级侧边栏权限体系。
- 登录后仅向服务端白名单命中的平台操作员展示“平台管理”入口；隐藏入口不能替代页面与 API 的服务端授权。
- MVP 范围包含：创建邀请、查看邀请列表/状态、重新生成邀请、撤销有效邀请、复制本次生成的开通链接。
- 创建表单至少包含目标邮箱、机构名称和可选备注；机构名称沿用现有必填约束。
- 邀请有效期在 MVP 固定为 7 天，不允许操作员自定义；过期后通过显式重新生成获取新链接。
- 邀请状态至少区分：待领取、已领取、已过期、已撤销。
- 明文 token/完整开通链接仅在创建或重新生成成功响应中展示一次；列表和后续详情不得恢复或展示历史 token。
- MVP 只生成并复制邀请链接，由平台操作员沿用现有方式人工发送；不自动发送 onboarding 邮件。

### R3. 服务端与数据一致性

- API 契约、平台授权、领域逻辑和数据库访问继续按现有 contracts/router/repository 分层。
- 创建发现同邮箱已有待领取邀请时返回冲突，不自动替换；只有操作员显式确认“重新生成”后才撤销旧邀请并返回新的单次可见链接。
- 创建/重新生成继续保证同邮箱同时至多一个待领取邀请；重新生成使旧 token 立即失效。
- 注册前置校验和最终领取必须在事务内重新绑定同一邮箱 + 同一 token，不允许旧 token 在并发重新生成后领取新邀请。
- 撤销必须幂等或返回清晰的状态冲突语义，不能影响已领取邀请创建出的机构和 owner。
- 保留现有注册闸门、token hash、邮箱匹配、事务锁定及机构初始化语义，不允许 Web UI 绕过。

### R4. 平台级审计与隐私

- 使用独立平台审计事件模型记录创建、重新生成、撤销和领取；不把现有强制关联 `organizationId` 的机构审计表改成 nullable。
- 平台审计必须记录平台操作员、目标邀请、时间和受控结果字段。
- MVP 不提供独立平台审计查看页面；邀请列表仅展示完成日常运维所需的创建人、创建时间、撤销时间和领取状态摘要。
- 平台审计不得记录明文 token、Cookie、密码或其他认证密钥。
- 机构创建完成后仍保留现有 `organization_onboarded` 机构审计事件；平台侧审计与机构侧审计职责需要明确区分并可关联 invitation ID。
- 列表及日志只返回/记录完成运维所需的最少个人信息。

### R5. 兼容、发布与回滚

- 现有受邀人 `/onboard` 流程和已签发邀请保持兼容。
- 数据库变更采用向前兼容 migration；发布期间旧脚本与新应用不得产生不一致状态。
- 试运行期保留 SSH 脚本作为紧急回退路径，但应避免脚本绕过新审计要求；设计阶段必须给出过渡策略。
- 回滚应用版本时，新表/nullable 字段可以保留，不执行破坏性 down migration。

## Confirmed Product Decisions

- 试运行期采用服务端平台操作员邮箱白名单；长期迁移到独立平台操作员权限模型。
- Web 入口使用独立 `/platform/onboarding` 路由，平台权限不依赖用户是否属于某个机构。
- 机构名称继续作为创建邀请的必填字段；默认占位名称由操作员明确填写，例如“待完善机构”。
- 邀请有效期固定 7 天，不提供自定义有效期。
- MVP 只生成/复制邀请链接，不自动发送邮件。
- 普通创建遇到同邮箱待领取邀请返回冲突；只有明确确认“重新生成”才使旧链接失效。
- 平台审计完整落库；MVP 邀请列表展示必要操作摘要，但不建设单独审计查看页面。
- SSH 脚本保留为受控的 break-glass 路径，并同步 Web 端状态与审计约束。

## Acceptance Criteria

- [ ] 非登录用户、邮箱未验证用户、未进入服务端白名单的用户均无法读取或写入平台 onboarding 数据。
- [ ] 普通机构 `owner/admin` 在不属于平台白名单时无法访问平台 onboarding API。
- [ ] 白名单平台操作员可以创建目标邮箱 + 机构名称的 7 天邀请，并只在成功响应中获得一次开通链接。
- [ ] 同邮箱已有待领取邀请时，普通创建返回冲突且旧链接继续有效；仅显式确认重新生成后旧链接才失效。
- [ ] 同邮箱重新生成后，旧 token 失效且新 token 可用于现有注册流程。
- [ ] 覆盖注册前置校验后并发重新生成的竞态：旧 token 不得领取新邀请。
- [ ] 平台操作员可以查看邀请状态并撤销待领取邀请；不能通过列表恢复明文 token。
- [ ] 受邀邮箱用有效 token 注册后，指定名称的机构与唯一 `owner` 在同一事务创建，邀请状态变为已领取。
- [ ] 创建、重新生成、撤销均产生不含明文 token 的平台审计记录；机构创建仍产生现有机构审计记录。
- [ ] API 对未认证、未授权、无效输入、状态冲突和系统错误返回不同语义。
- [ ] 自动化测试覆盖白名单边界、邮箱验证、token 单次返回、重发撤销旧 token、撤销/过期/已领取状态、并发与审计原子性。
- [ ] Web 实际验证覆盖加载、空态、错误态、提交中、防重复提交、复制成功和移动端可用性。
- [ ] 发布说明包含白名单配置、migration 顺序、旧脚本过渡和回滚步骤。

## Out of Scope (Initial)

- 本任务不实现完整的平台账号生命周期、权限分组或多角色 RBAC 管理后台。
- 本任务不新增 onboarding 邮件模板、自动投递、投递状态、失败重试或邮件重发能力。
- 本任务不提供自定义邀请有效期；若后续有真实需求，再评估 1/3/7/14 天等受控选项。
- 本任务不建设通用平台审计日志页面、审计筛选器或平台审计中心。
- 不允许机构管理员自行创建其他机构或授予其他机构的 `owner`。
- 不开放公开注册，不降低现有 token 与邮箱绑定规则。
- 暂不把“提高认证限流阈值”作为本功能的一部分；相关登录循环由独立 Issue #67 跟踪。
