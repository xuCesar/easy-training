# 学员业务时间线

## 目标

在学员详情提供可分页、可追溯的统一业务时间线，使获授权的校区人员能从一个视图回答学员何时报名、产生哪些应收与收退款、参加哪些课次及课时如何变动，而不修改既有资金和教学事实。

## 已确认事实

- GitHub #27 是父路线图 #6 的 P1 子任务，依赖已关闭的 #25，并复用既有报名、账单、收款、续费、转课、退款、考勤、课消、报名生命周期和机构审计事实。
- 当前 `training.students.detail` 仅返回档案、联系人和标签；管理端学员页尚无业务时间线。
- `attendance`、`lessonConsumption`、`invoice`、`payment` 与报名生命周期事件已有稳定主键和时间字段；`lessonConsumption` 记录课时变动前后余额。
- 学员档案目前只有当前 `status`，没有历史状态事件；要满足状态事件展示，需要新增仅追加的状态变更事实，无法可靠回填旧状态的真实变更时间与操作者。
- 既有学员查询按机构和校区范围限制；时间线必须沿用服务端权限裁剪，教师不得借此读取财务或联系人敏感信息。

## 需求

1. 在学员详情中展示按确定顺序倒序排列的统一时间线，聚合：报名创建、入班/转班、账单、收款、续费、转课、退款、考勤、课消与学员状态事件。
2. 每项至少展示类型、业务发生时间、摘要、操作人及获授权时可用的来源跳转；取消、退款等反向动作作为新事实展示，不覆盖原记录。
3. 不复制资金或课时事实。时间线的稳定标识、排序、分页游标均由服务端定义。
4. API 必须按机构、角色和校区范围返回；受限角色不能通过时间线或来源标识越权取得财务、联系人或其他校区数据。
5. UI 完整覆盖初始加载、加载更多、空态、错误重试和移动端展示。

## 排序规则

- 考勤与课消以课次开始时间作为业务发生时间；若实际登记或课消写入时间不同，摘要同时显示该时间。补录历史考勤因此回到对应课次的历史位置，而非置顶。

## 来源跳转

- 首期补齐受权限保护的深链接：时间线的账单、课次等事件可直接定位到对应详情；页面自身仍须按角色和校区范围验证，不得因 URL 参数绕过访问控制。

## 历史兼容

- 只记录本功能上线后的真实状态变更；不为旧学员回填或伪造状态基线。既有学员仍可展示可验证的报名、资金、课次与课消事实。

## 验收标准

- [x] 在有权限的学员详情可分页追溯从报名到收款、上课及课消的事件；退款等反向动作不覆盖原记录。
- [x] 每项拥有稳定标识与确定排序，同一时间的并发事件不会随机跳动。
- [x] 机构、校区和角色权限均在服务端生效；受限角色不能读取隐藏事件或以来源 ID 越权访问资源。
- [x] 空、加载、错误、加载更多和移动端状态完整。
- [x] PostgreSQL 集成测试、类型检查、规范检查与构建通过。

## 非范围

- 跨学员全局时间线、经营分析、附件预览、外部通知。
