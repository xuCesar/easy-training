# P2 核心经营指标

## Goal

把招生、到课、消课和续费从当前实时快照升级为有稳定事实、明确时间口径和可追溯定义的经营指标，让管理者无需人工汇总即可判断招生和教学经营状况，并为 T6 经营对比与 T7 报表提供唯一数据基础。

## Background

- 现有运营工作台只提供当前待跟进、累计报名、近期课次等实时快照，不具备历史范围、对比、cohort、指标版本或数据质量语义。
- 报名已有可空且冻结的 `conversionOwnerUserId`；线索只有当前 `ownerUserId`，没有稳定提供人、负责人变更历史或可重放结案周期。
- 直接报名已有独立 `enrollmentRegistration` 事实且不创建线索，但尚未保存报名来源或提供人。
- 考勤、不可变课消、补课、续费、转课和冻结/复课事件已经存在；当前报名的累计购买课时不能表示最近一次购买周期，也没有不可变续费机会。
- 本任务继续使用 PostgreSQL、Drizzle、Zod/oRPC、TanStack Query 和现有 UI，不引入数仓、BI、缓存服务或图表依赖。

## Requirements

### R1. Common Metric Contract

- 默认范围为 `Asia/Shanghai` 自然月月初至当前时刻，并与上月相同已过天数比较；支持最近 7/30/90 天、本月、本季度、本年度和最长 2 年自定义范围。
- 所有区间左闭右开。滚动和自定义范围比较紧邻的等长前序区间；自然月/季度/年度比较上一自然周期的相同已过时长，不能超过对比周期末端。
- 事件指标按业务发生时间，快照指标按结束时点，cohort 指标同时返回观察窗和成熟度；未成熟 cohort 不生成误导性环比。
- 90 天内按上海自然日、超过 90 天按周一开始的上海自然周、超过 1 年按上海自然月聚合。
- 无分母、样本不足或事实覆盖不足时返回 `null/notApplicable` 和稳定原因，不显示为 0%。
- 每个响应包含契约版本、指标定义版本、时区、生成时点、主范围、对比范围、聚合粒度、分子/分母、诊断数量和数据质量提示；页面、下钻及后续导出必须复用同一服务端定义。

### R2. Sales Attribution and Funnel

- 区分线索提供人、当前跟进负责人、转化业绩归属人和操作人。提供人用于获客贡献，当前负责人用于过程管理，转化归属用于顾问成交，操作人只用于审计。
- 线索创建/导入时保存稳定且可空的提供人；负责人每次变化保留历史；结案时冻结当时校区、负责人和结论归属。除受审计纠错外不改写历史，首期不支持多人或比例拆分。
- 顾问转化率按所选期间内的结案周期计算：成功结案周期数除以成功结案周期数加流失结案周期数。每个周期只允许一个结论；线索流失后重新打开会开启新周期，原流失周期保留，后续成交计入新周期。
- 转化和流失按结案时冻结归属，未分配单列；开放周期另列在跟数量和实时阶段分布。
- 招生漏斗以所选期间创建的线索为 cohort，观察创建后 30 天内真实发生的已联系、已约试听、首次转化和已流失里程碑；允许跳过阶段，不补造未发生事实。
- 未满 30 天的 cohort 返回未成熟标记。当前阶段分布是独立快照；线索提供人的获客转化使用同一 cohort 和观察窗。
- 没有线索的报名是直接报名，不生成合成线索。直接报名独立保存来源、可空提供人、成交归属和发生时校区；进入总报名及顾问直接报名人数/成交金额，不进入线索漏斗或顾问线索转化率。

### R3. Attendance and Consumption

- 主到课率只统计正常班级已完成课次：`(present + late) / (present + late + absent + leave)`；同时返回迟到率、请假率和缺勤率。
- 取消、未完成和未来课次不进入分母。补课考勤不回写原课次或主到课率，另以补课完成率、未完成数量和待重排数量展示。
- 班级成员范围按课次发生时的报名生命周期重放，后续冻结、复课、转班或退班不能改写历史应到人数。
- 消课趋势使用不可变 `lessonConsumption`，每条实际课消计 1 课时，按关联 `lesson.startsAt` 的上海业务日期归属；主课和实际完成的补课均计入真实消课。
- `consumedAt - lesson.endsAt` 只作为录入延迟诊断，不改变业务日期；晚于课次结束 24 小时的记录进入数据质量计数。

### R4. Renewal Opportunity Cohort

- 初始报名和每次真实续费开启独立购买周期，保存本周期购买课时、开始时间和来源事实；不得使用会累计变化的当前报名字段代替最近购买周期。
- active 报名在某购买周期内剩余课时首次降到本周期购买课时数的 20% 或以下时生成不可变续费机会，阈值向上取整且至少 1 课时；机会记录周期、触发时间、阈值、发生时校区和观察窗。
- 机会触发后 30 个有效观察日内创建续费业务记录并正式增加课时时计为成功，不等待对应账单实际收款；一条续费最多完成一个机会，并开启新购买周期。
- 冻结期间暂停观察窗并在复课后继续；仍处于冻结的机会不成熟。不能用当前余额倒推上线前首次达到阈值的时间。
- 机会形成前发生的提前续费单列且不进入机会分母；转课作为课程延续单列且不算续费。
- 同时返回续费机会数、成功/未成功/未成熟数量、续费成交金额、续费课时和剩余观察时间；账单实收与回款由 T6 财务指标独立衡量。

### R5. Authorization and Privacy

- owner/admin 查看全机构；campus_manager 查看授权校区；所有历史指标按事件发生时校区裁剪，不能使用学员当前校区改写历史范围。
- consultant 只查看本人提供、本人结案归属和本人直接报名表现，可查看脱敏校区基准但不能查看其他顾问姓名或实名下钻。
- 顾问校区基准只在所选范围内至少有 5 个有效结案周期时返回；不足时返回 `notApplicable/insufficientSample`。
- teacher 只查看本人授课课次的到课和消课指标，不能查看其他教师；finance 无权读取本任务的招生和教学指标，服务端返回明确 `FORBIDDEN`，不能以空数据代替无权。
- 未分配提供人、负责人或结案归属只对 owner/admin/campus_manager 显示。

### R6. Data Quality, Compatibility and UI

- 对缺失历史提供人/归属、上线前无里程碑或购买周期、未成熟 cohort、晚录课消、无有效分母和样本不足返回稳定数据质量计数，不通过当前快照猜测回填。
- 只对现有不可变事实能够明确证明的记录做有来源标记的迁移；无法证明首次发生时间的历史机会不补造。
- 新经营分析页面与当前实时工作台分离，按角色只展示可访问的招生、到课、消课和续费区块；支持范围选择、对比、趋势、口径说明、下钻、加载、空、错误、无权、未成熟和数据质量状态。
- 桌面与 390px 布局均可用；图形之外必须提供文本数值和可访问名称，不因无数据或无权限导致横向溢出或误导性空白。

## Acceptance Criteria

- [x] 公共契约统一返回上海时区、主/对比范围、粒度、契约/定义版本、分子/分母及数据质量语义，滚动和自然周期比较符合 R1。
- [x] 提供人、负责人历史、结案周期、成交归属和操作人互不混用；重新打开不会覆盖原流失结论，后续负责人或转校不会改写历史指标。
- [x] 30 天线索 cohort、直接报名、结案周期转化率和开放线索快照按 R2 分开展示，跳阶段不产生虚假事实。
- [x] 主到课率、迟到/请假/缺勤、补课完成率和待重排数量使用正确课次及发生时成员范围；消课按课次业务日期而非录入日期归属。
- [x] 购买周期、低课时机会、冻结暂停、30 个有效观察日成功、提前续费和转课可被历史重放，续费率不依赖付款状态或当前累计余额回算。
- [x] 五类角色和校区范围符合 R5；顾问/教师无实名同业数据，顾问基准少于 5 个有效结案周期时不返回数值，finance 得到明确无权响应。
- [x] 页面、下钻以及 T6/T7 调用同一版本化服务端指标定义，不在浏览器或报表中复制指标算法。
- [x] 固定 fixture 的指标金值测试、权限/机构隔离测试、迁移/双写测试、类型检查、Biome、生产构建和桌面/390px 浏览器验证通过。

## Dependencies and Out of Scope

- GitHub 实施跟踪：#38；统一关联路线图 #6。
- 依赖现有线索、报名、考勤、课消、补课、续费、转课和冻结事实；以 additive migration 补稳定归属、里程碑、购买周期和续费机会。
- T6、T7 必须复用本任务的时间解析、权限范围、指标服务和版本，不得另写同名算法。
- 不提供预测、经营目标拆解、销售提成、多人业绩分摊、AI 建议、外部广告归因、行业基准、数据仓库或财务回款分析。

## Rollout and Rollback

- 先部署 additive schema 和仍保持隐藏的事实双写，再以固定 fixture 与真实数据质量执行 shadow read，最后开放经营分析页面。
- 回滚时关闭指标读取和 UI，但继续保留稳定事实 writer；旧实时工作台继续运行。生产回滚包不得退回到完全不写新事实的旧版本，否则恢复后会形成永久时间断层。
