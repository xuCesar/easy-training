# 实施计划

## 1. 公共契约与时间内核

- [x] 在 `packages/api` 定义经营指标输入、版本化 envelope、可用/不可用判别联合、数据质量和各区块响应类型。
- [x] 实现可注入 `now` 的上海时区范围解析器，覆盖 7/30/90 天、月/季/年、自定义、等长对比、同周期已过时长、左闭右开和日/周/月粒度。
- [ ] 建立指标定义 registry 与 `getBusinessMetrics(scope, query)`，确保主范围、对比、下钻和后续 T6/T7 使用同一实现。

## 2. Schema 与 additive migration

- [x] 为 lead 增加提供人/创建校区快照和当前周期号；新增负责人分配事件、里程碑事件及机构/线索/周期唯一约束和查询索引。
- [x] 为 enrollment/enrollmentRegistration 补成交归属姓名、发生时校区、直接报名来源与提供人快照；旧字段保持 nullable 兼容。
- [x] 新增购买周期、续费机会和机会转化表，定义来源、sequence、阈值、FK、CHECK、唯一约束及时间/校区索引。
- [x] 生成并审查 Drizzle migration；只迁移不可变事实能够明确证明的数据并标记 provenance，不用当前快照补造历史。

## 3. 招生事实双写

- [x] 抽取 transaction-aware 线索事实 writer，接入单条创建、CSV 导入、负责人更新、跟进阶段、流失、重开和转化路径。
- [x] 为新线索保存可空提供人并写初始负责人事件；负责人变更保存 before/after，操作人不得被推断为负责人。
- [x] 实现 contacted/trial_booked/lost/reopened/converted 首次里程碑和结案周期状态机；同周期只有一个结论，重开递增周期且不改写原流失。
- [x] 扩展线索转化和直接报名契约/UI，保存来源、提供人、成交归属和发生时校区快照；保持 direct enrollment 不生成 lead。
- [ ] 覆盖原写入失败、事实写入失败、幂等重放和并发结案，确保领域事实与分析事实同事务成功或回滚。

## 4. 购买周期与续费机会双写

- [x] 初始报名和续费事务创建唯一递增购买周期，保存本周期课时、余额、金额、来源和校区；转课只记录延续 provenance。
- [x] 在结课课消事务中使用扣减前后余额和当前周期原子生成首次低课时机会；唯一约束防止重试/并发重复。
- [x] 续费事务锁定开放机会：有效观察窗内写成功 conversion，否则记录提前续费；成功定义不等待账单收款。
- [ ] 实现基于 frozen/resumed lifecycle event 的有效观察时长计算，覆盖多次冻结、持续冻结、边界时刻和缺失配对诊断。
- [ ] 验证转课不算续费、提前续费不进机会分母、新续费开启新周期且旧机会不被后续周期重复完成。

## 5. 指标 repositories 与权限

- [ ] 实现 sales 聚合：结案周期转化率、开放周期快照、30 天创建 cohort、提供人贡献和直接报名；跳阶段不补里程碑。
- [ ] 抽取/复用课次时点报名成员回放内核，实现主到课、迟到/请假/缺勤、补课完成/未完成/待重排指标。
- [ ] 实现按 lesson.startsAt 上海业务日期的消课趋势和超过 24 小时晚录诊断。
- [ ] 实现购买周期机会 cohort、30 个有效观察日成熟度、成功/未成功、提前续费、成交金额和课时指标。
- [ ] 建立角色—指标—范围矩阵：管理者机构/校区范围、顾问本人销售和至少 5 个结案的脱敏基准、教师本人课次、finance 明确无权。
- [ ] 所有查询同时限制 organizationId 与发生时 campus/owner/teacher，检查最长两年 explain plan 后只增加必要索引。

## 6. oRPC 与经营分析 UI

- [ ] 新增 sales/attendance/consumption/renewal 查询和受控下钻 oRPC procedure，统一错误映射；客户端不能提交 organizationId、campusIds 或越权身份。
- [ ] 新增 `/analytics` 路由和导航入口，按角色只请求/呈现允许区块；保留 `/dashboard` 现有实时工作台兼容。
- [ ] 实现范围筛选、指标卡、趋势、对比、分子/分母、cohort 成熟度、口径说明和数据质量提示，不在组件中计算业务公式。
- [ ] 覆盖加载、错误、真实零值、空、无权、样本不足、事实覆盖不足和未成熟状态；下钻重新请求服务端授权数据。
- [ ] 使用现有 UI 与轻量 CSS/SVG 完成可访问桌面和 390px 布局，不新增图表依赖或横向滚动核心内容。

## 7. 测试与质量门

- [ ] PostgreSQL 固定 fixture 金值测试覆盖范围边界、比较范围、周/月桶、无分母和数据质量原因。
- [ ] 招生测试覆盖提供人/负责人/操作人分离、负责人变更、流失—重开—成交多周期、跳阶段、直接报名和旧事实缺口。
- [ ] 教学测试覆盖 normal/makeup 混合课次、发生时成员回放、四类考勤、取消/未来/未完成排除、补课待重排和晚录课消。
- [ ] 续费测试覆盖初始/多次购买周期、阈值向上取整、首次触发、提前续费、30 天边界、多次冻结暂停、持续冻结、转课及付款未完成仍算成交。
- [ ] 权限测试覆盖全部角色、跨机构、校区变更、顾问本人/同业隔离、4/5 个样本边界、教师绑定和 finance FORBIDDEN。
- [ ] 运行 migration 生成/应用、相关与全量 `pnpm test:integration`、`pnpm check-types`、`pnpm check`、`pnpm build` 和 `git diff --check`。
- [ ] 浏览器验证 owner、campus_manager、consultant、teacher、finance 的桌面/390px 页面，以及加载、错误、空、样本不足、未成熟、下钻和无横向溢出。

- [ ] 开放 reader 前确认所有新增业务写路径已双写，事实失败会回滚原事务，旧版本回滚包仍保留 writer。
- [ ] 开放顾问/教师页面前确认 repository 级本人范围、小样本保护和下钻重验，响应不含同业身份或未分配可推断数据。
- [ ] 开放 T6/T7 复用前锁定 `contractVersion=1` 与首个 definitionVersion，金值 fixture 覆盖所有公开指标。
- [ ] 对两年范围执行真实数据量 explain/耗时检查；如未达到性能目标，先补针对索引，不在本任务引入缓存或预聚合。
- [ ] 回滚只关闭 `/analytics` 和指标 reader，保留 additive schema、事实 writer 和旧 dashboard；禁止删除已产生的历史事实。
