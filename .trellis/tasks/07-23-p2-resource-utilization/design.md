# P2 教师与班级资源利用分析设计

## Scope and Boundaries

本任务只交付资源利用的持久化历史、服务端分析契约和测试，不改变既有排课、考勤、报名或班级生命周期规则，也不提前实现多维经营对比页面。后续对比页面只消费本任务的稳定查询结果。

## Data Model

- 新增 `teacher_capacity_history`：机构、教师、每周标准授课分钟、生效日期、创建时间和创建人；同一教师的生效日期唯一。
- 新增 `class_group_capacity_history`：机构、班级、容量、生效日期、创建时间和创建人；同一班级的生效日期唯一。
- 现有 `teacher.weeklyCapacityHours` 与 `class_group.capacity` 继续保存当前配置，保持既有教务读写兼容；创建时写入首个容量版本，容量变更时在同一事务写入或更新当天版本。
- 不回填上线日以前的历史。容量版本覆盖不足的查询以数据质量和 `notApplicable` 返回，不使用当前配置猜测过去。

## Metrics

- 教师容量分钟按查询区间与生效区间相交的上海自然周折算；容量缺失或只覆盖部分范围分别返回未配置和覆盖缺口。
- 实际利用率的分子为范围内、已完成且未取消课次的授课分钟；计划利用率的分子为范围内、未取消计划课次分钟。两者均按课次的教师归属统计，不因补课学员重复增加时长。
- 当前班级席位只统计 `recruiting`、`running` 状态班级中的 `active` 报名；每班对学员去重，同一学员跨班分别占位。
- 满班为席位数大于等于容量，接近满班为占用率大于等于 90% 且未满。课次上座率以已完成正常课次的发生时容量为分母，并只使用该课次时点有效成员。

## API and Authorization

- 在既有 `training.analytics` 下新增资源查询，复用 `businessMetricQueryInputSchema`、范围解析、时区、版本信封和 `campusAccess`。
- 复用既有教师与班级维护入口增加“容量生效日期”字段；它只影响新建或更新的容量版本，不改变排课可用时段，也不提供独立资源分析看板。
- owner/admin 查询全机构；campus_manager 只查询授权校区；teacher 只查询绑定教师的利用率和其班级教学事实；consultant、finance 返回明确无权。
- 查询服务端返回容量、授课分钟、课次数、比率、超负荷标记及数据质量计数；页面层不得重算指标。

## Compatibility and Rollback

- migration 仅新增表与索引，不修改或删除现有数据。
- 先将当前配置写为上线日的首个版本，再开放更新路径与 reader；旧记录的历史区间明确显示覆盖不足。
- 回滚时关闭新增 reader 与写入入口，保留容量历史，不能用逆迁移删除已形成的经营事实。
