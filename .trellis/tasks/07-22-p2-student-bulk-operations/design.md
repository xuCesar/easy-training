# 技术设计

## 1. 边界与原则

本任务在既有 `packages/db`、`packages/api` 和 `apps/web` 分层内完成，不新增依赖或独立导入服务。Zod/oRPC 是公开契约，API 只传递服务端解析的机构、成员和校区上下文，数据库 repository 负责事务、授权重验、幂等、并发和审计。

学员当前运营负责人、销售转化归属和操作人是三类不同事实：

- 学员负责人是可变当前态，服务于后续运营，并保留不可变分配事件。
- 转化业绩归属在报名时明确并冻结，后续学员负责人变化不得改写。
- 操作人只进入领域事件或审计，不推断为负责人。

历史学员不回填负责人。上线后所有既有和新增学员写路径共同维护统一的学员数值版本，批量入口才可开放。

## 2. 数据模型与迁移

对 `student` 做 additive 变更：

- `ownerUserId text null`，关联用户并使用 `onDelete: set null`；业务资格仍以当前机构成员关系校验，不能只信任用户外键。
- `version integer not null default 1`，负责人、标签、联系人、状态、合并等改变档案语义的成功写入递增；纯 no-op 不递增。
- 增加机构/校区/负责人筛选索引，支持“未分配”查询。

新增 `student_owner_assignment_event`：机构、学员、校区快照、前后负责人、操作人、来源、可空批次 ID 和发生时间。来源限定为 `manual`、`import`、`lead_conversion`、`direct_enrollment`、`bulk`、`merge`、`authorization_revoked`。事件只追加，不通过修改结束时间维护区间。

新增 `student_import_batch`：机构、外部 requestId、输入哈希、创建人、总行数、成功/错误数、固化逐行错误、创建时间；机构内 requestId 唯一。批次不保存 CSV 原文或联系人明文。

新增 `student_bulk_operation_batch`：机构、外部 requestId、输入哈希、操作类型、目标数、变化数、无变化数、目标 ID、操作者和创建时间；机构内 requestId 唯一。班级生命周期子事件关联该批次，并继续保留逐报名 before/after 事实。

为报名冻结归属补充最小兼容字段：报名保存可空的 `conversionOwnerUserId`，线索转化默认当前已确认的转化归属但允许表单调整；直接报名允许显式选择或保持空。该事实只用于成交归属和新学员负责人默认值，不随学员负责人改变。选择已有学员时不自动覆盖当前负责人；管理角色明确勾选后才在同一报名事务追加负责人事件。

迁移只增加 nullable 字段、带默认值的版本、事件/批次表、枚举和索引，不回填历史负责人或转化归属。生成的 Drizzle migration 与 schema 同步提交。

## 3. 学员版本与负责人资格

学员列表/详情返回 `version`、可空负责人 ID/姓名；列表新增负责人筛选，支持具体成员和 `unassigned`。单条更新、合并和所有创建/转换路径改为维护 `student.version`；单条编辑提交使用 `expectedVersion`，不再把时间戳作为新的并发契约。`updatedAt` 保留展示用途并随成功变更推进。

负责人候选必须同时满足：

- 仍是当前机构成员；
- 角色为 owner/admin/campus_manager/consultant；
- 全机构访问，或明确拥有学员校区权限。

成员移除、角色改为 teacher/finance，或校区范围缩小时，成员管理预览返回将失去资格的学员数量。确认变更在成员管理同一事务按学员 ID 排序锁定受影响记录，清空 owner、递增版本并追加 `authorization_revoked` 事件；成员审计只增加受影响数量和学员 ID，不复制姓名或联系方式。

学员合并预览把负责人差异作为显式冲突，提交沿用现有字段来源选择，不做启发式合并；需要改变主档负责人时追加 `merge` 事件。

## 4. CSV 导入与导出

### 4.1 统一传输和解析边界

复用线索 CSV 的浏览器可用 UTF-8 envelope 字节计算与 256 KiB RPC 限制，DB 防线最多 500,000 字节、1000 个数据行。只接受 UTF-8 CSV 和严格唯一表头；拒绝列数溢出、未闭合引号、非法日期/状态/手机号、字段超长及以 `= + - @` 开头的可执行公式值。

模板列固定为：姓名、校区编码、主要联系人姓名、主要联系人手机号、出生日期、状态、负责人邮箱、已有标签。状态使用共享状态代码，空值为 `trial`；标签用 `|` 分隔并按既有标签规范化规则精确解析，只允许机构内启用标签。

### 4.2 预览

预览解析文件并按当前权限读取校区、负责人、标签和重复候选，返回总行数、有效行数和稳定的逐行问题列表。预览不写库、不产生审计，也不是锁或授权凭证。

文件内手机号按现有 `normalizeStudentPhone` 规范化后去重。同机构现有 `student.guardianPhoneNormalized` 或任一 `studentContact.phoneNormalized` 命中即阻断：操作者有权访问候选校区时返回脱敏候选及学员链接；仅命中无权校区时返回泛化重复提示。

### 4.3 确认与幂等

确认的输入哈希覆盖原始 CSV 内容和所有影响语义的确认参数。事务开始后先声明 `(organizationId, requestId)`：

- 同 requestId、同哈希且已有完成批次，直接返回首次固化结果，不重新解释当前数据；
- 同 requestId、不同哈希返回幂等冲突；
- 首次确认重新解析、读取当前成员权限并重新校验全部引用和重复。

所有学员创建路径按规范化手机号排序获取机构级 advisory lock，确认导入随后在事务内重查同机构全部联系人，避免导入与单条建档竞态。权限或数据变化转为逐行错误；剩余有效行作为一个集合写入学员、主要联系人、兼容 guardian 字段、负责人事件和标签。有效行、批次结果和一次中央审计同事务提交。未知数据库/系统错误回滚整批，不报告部分成功。

### 4.4 导出

导出使用独立的管理角色 procedure，仅 owner/admin/campus_manager 可调用，并在 repository 再次按当前校区范围裁剪。沿用当前学员筛选和确定性排序，最多 5000 名学员，一名学员一行，只导出主要联系人完整姓名和手机号；其他联系人不进入 CSV。

字段包含学员 ID、姓名、校区编码/名称、出生日期、状态、负责人姓名/邮箱、主要联系人姓名/手机号、标签、创建/更新时间。输出 UTF-8 BOM CSV，所有单元格引号转义并防公式注入。中央审计仅记录筛选摘要、结果数量和操作者，不保存 CSV 或联系人值。

## 5. 原子批量调整

### 5.1 API 契约

预览和提交使用判别联合，单批最多 200 个显式且不重复的目标：

- `setStudentOwner` / `clearStudentOwner`：`{ studentId, expectedVersion }[]`；
- `addStudentTag` / `removeStudentTag`：`{ studentId, expectedVersion }[]`；
- `assignEnrollmentClass` / `withdrawEnrollmentClass`：`{ enrollmentId, expectedVersion }[]`。

提交额外包含 requestId 和目标负责人、标签或班级 ID。预览逐项返回 `change | no_change | blocked`、受控 before/after 摘要和稳定 blocker code。提交不信任预览结果，重新执行完整规划。

负责人/标签批量按学员 ID 排序锁定，重验管理角色、校区、版本及负责人/标签资格。no-op 仍校验版本但不递增版本。全部目标校验通过后统一写当前态、版本、负责人事件和批次审计；任一阻断全部回滚。

### 5.2 班级生命周期共享内核

不能在批量事务中循环调用当前自行开启事务的 `updateEnrollmentLifecycleRecord`。将其拆为接收已有 transaction 的共享规划/应用内核：单条 wrapper 自行开启事务，批量 repository 在一个外层事务调用同一内核。

共享内核按稳定顺序锁定成员权限、全部报名、涉及的来源/目标班级、相关 active 报名、未来 scheduled 课次和教室。批量容量和重复校验以“整批应用后的最终状态”计算，正确处理同批移出、移入和换班，不依赖目标遍历顺序。

全部校验成功后统一递增 enrollment version，并为每个实际变化追加独立 lifecycle event；子事件使用内部 requestId 并关联批次，外部 requestId 只在批次表唯一。批次重放在进入内核前短路。中央审计只写一次批次摘要，逐报名完整事实留在 lifecycle event，避免重复审计和联系人泄露。

报名创建、线索转化和生命周期变更至少复用同一班级资格/容量 validator 与锁顺序，防止不同入口规则漂移。

## 6. API、UI 与权限

API 新增：负责人候选、导入预览/确认、受限导出、批量预览/提交和成员负责人影响预览。导入挂在允许 consultant 的学员管理过程；导出和管理型批量使用仅 owner/admin/campus_manager 的专用过程。DB 层仍重新读取当前成员关系，不能只依赖 router middleware 快照。

学员页增加负责人/未分配筛选、CSV 模板/导入/导出入口、多选列和批量动作栏。选择仅保存明确 ID，最多 200 项；筛选或分页变化不自动扩展选择。班级动作选择的是 active enrollment，并展示课程、当前班级和版本，不能从学员猜测报名。

导入对话框沿用“选文件—预览—确认”模式，区分格式错误、逐行错误、幂等冲突和系统失败。批量对话框先展示变化、无变化和阻断项；提交冲突后保留选择并提示刷新重预览。桌面表格与 390px 紧凑列表均提供可访问的选择、加载、空、错误和提交中状态。

## 7. 审计、兼容、发布与回滚

新增中央审计动作覆盖学员导入、学员导出和学员批量调整。审计与领域写入同事务，只保存批次 ID、动作、数量、目标 ID、校区及 requestId 等白名单；负责人前后值保存在专属事件，班级前后值保存在 lifecycle event，不记录 CSV 原文、联系人、标签自由文本或完整导出内容。

发布分两层：

1. 先应用 additive migration，并发布兼容基线：所有旧学员写路径维护数值版本，读接口支持 nullable owner 和未分配筛选，但隐藏批量入口。
2. 再启用转化/直接报名归属、导入导出、负责人/标签批量；完成共享生命周期内核和跨路径锁序测试后开放班级批量。

回滚时关闭新入口和写路径，保留负责人、事件、批次与审计数据，并回到仍维护 `student.version` 的兼容基线。不得回滚到完全不递增版本的旧代码，否则会绕过批量并发保护。现有单条学员、报名和班级读取继续兼容 nullable 新字段。

## 8. 关键风险与控制

- 跨校区重复：导入碰撞查询必须覆盖同机构全部联系人，但响应按当前校区权限脱敏。
- TOCTOU：确认与批量提交在事务内重读当前成员、校区、负责人和标签资格。
- 版本漂移：所有学员聚合写路径共同递增数值版本，标签/负责人关系变化也不能漏掉。
- 嵌套事务与部分提交：批量班级变更使用共享 transaction-aware 内核，不循环调用公开单条命令。
- 容量顺序依赖：按整批最终状态计算班级和未来课次教室占用。
- 非法负责人：成员权限变更同事务清空并记历史，不静默保留。
- 隐私：跨无权校区重复只返回泛化错误；CSV、联系人和自由文本不进入中央审计。
