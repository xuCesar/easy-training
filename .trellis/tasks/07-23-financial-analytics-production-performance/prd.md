# 财务分析生产数据量性能验收

## Task Status

- 当前状态：已完成本地 mock 性能验证，生产等量复测已移出当前 P2。
- 排期定位：未来上线门禁，不计入当前研发阶段的 P2 功能完成度。
- 恢复条件：生产等量脱敏只读副本、代表性高/低基数参数、可接受性能阈值和受控执行权限均已明确。

## Goal

在生产等量数据环境对财务 summary、资金事件下钻和账龄下钻执行
`EXPLAIN (ANALYZE, BUFFERS)`，以真实计划决定是否需要补充索引，形成可审计的上线性能结论。

## Background

- P2 财务经营分析功能、权限和本地 PostgreSQL 金值测试已经完成；本地 fixture 不能证明生产数据量上的查询计划与 I/O 成本。
- 当前实现限制查询区间最长两年，且不引入缓存、物化视图或预聚合；只有真实慢路径才允许新增索引。
- 本任务独立于 P2 功能交付，不改变已归档的财务指标契约、业务语义或 reader 行为。

## Requirements

- R1：在经过脱敏或受控访问的生产等量 PostgreSQL 环境中，对主/对比范围的 financial summary、事件下钻和账龄下钻记录实际执行计划、执行时间、共享缓冲区读写与返回行数。
- R2：覆盖全机构和受限校区两种范围，以及最长两年范围；参数应使用具有代表性的高基数与低基数校区，避免只测空结果。
- R3：以基线/目标阈值和实际计划为依据决定索引。若无慢路径，不新增猜测性索引；若新增索引，必须 additive、可回滚并经迁移与同样 explain 复核。
- R4：产出不包含学员隐私、支付参考号、真实机构标识或完整连接串的性能记录，说明数据规模、查询形态、计划摘要、结论、索引决策与发布建议。
- R5：不改变财务指标口径、鉴权边界、API 契约或业务写入逻辑；如发现功能性缺陷，应另建修复任务。

## Acceptance Criteria

- [ ] 三类财务查询在真实等量环境完成 `EXPLAIN (ANALYZE, BUFFERS)`，记录覆盖 R2 所述范围和查询窗口。
- [ ] 性能记录可复核且不泄露敏感数据，明确说明数据规模、计划摘要和 I/O/耗时。
- [ ] 索引决策有证据：无变更时记录原因；有变更时 migration、回滚说明、测试和复测均通过。
- [ ] 得到明确上线结论：允许开放 reader，或列出阻塞项与负责人/下一步。

## Out of Scope

- 生产数据迁移、缓存/物化视图、预聚合、指标口径变更和前端页面改造。

## Resume Gate

- 在上述恢复条件全部具备前保持延期；本地 `easy-training-mock` 结果只能用于发现明显慢路径和验证索引效果，不能替代最终上线结论。
