# 收据与付款凭证

## Goal

为有效收款提供机构内唯一、不可静默改写、可按需查看和打印的凭证，并为后续合并开具、自动开具和服务端渲染保留稳定扩展边界。

## Background

- 账单详情已有付款、退款和调整历史，但没有独立凭证事实或编号。
- 系统没有电子发票、税务或外部支付平台集成；本任务只生成机构内部收款凭证。
- `payment`、批准后的 `refund` 和收款冲正均为不可变资金事实。

## Requirements

- 首版每条 `payment` 按需生成一张凭证；首次生成时分配编号并保存快照，正常收款事务不依赖凭证生成。
- 凭证与资金事实使用可扩展关联边界，首版不提供但允许未来一张凭证关联多条收款。
- 编号格式为 `RCP-YYYYMM-NNNNNN`，序号在机构和生成自然月范围内递增，固定六位，不按校区重置。
- 编号由系统分配，不可修改或复用；作废与事务回滚允许造成断号。并发生成不得重复编号。
- 凭证快照至少包含机构、校区、学员、账单摘要、本次收款、付款方式、收款时间、关联号和生成操作人所需展示字段；交款对象首版使用账单所属学员，不新增任意付款人字段。
- 同一收款任何时刻最多一张有效凭证；重复点击或相同请求重放返回当前有效凭证，不重复占号。
- 已生成凭证不可编辑或删除；财务四角色可在自身校区范围内填写必填原因后作废，作废不改变资金事实。
- 作废凭证永久保留并明确标记；可基于同一收款补开新编号凭证，新凭证引用原作废凭证。
- 补开只能调整抬头、备注等允许变化的展示字段，不得改变机构、校区、学员、账单、收款金额、方式、时间或资金关联。
- 退款或冲正不自动作废凭证，也不自动生成更正凭证；历史快照保持不变，查看和重新输出时附加当前资金状态。
- 部分/全部冲正分别展示原收款、累计冲正和当前有效金额；账单级退款只提示“关联账单存在退款”及累计退款额，不归属到某张收款凭证。
- 首版提供系统内详情、专用打印样式及浏览器打印/另存 PDF；输出包含凭证编号和查询/打印时间。
- 收款列表和账单详情展示“未开具 / 有效 / 已作废”状态与快捷入口；按需生成失败不得影响原收款。
- 凭证领域事实、类型化展示模型和渲染器保持分层，为未来自动/批量开具、多笔合并和服务端 PDF 保留稳定输入契约。
- 凭证生成、作废和补开写中央审计，但作废原因等自由文本只保留在领域事实中。

## Acceptance Criteria

- [ ] 授权用户可从具体收款生成、查看、作废、补开并打印凭证，未开具与当前状态清晰可见。
- [ ] 机构级编号在并发和跨校区场景唯一；历史编号永不复用，同一收款不会出现两张同时有效凭证。
- [ ] 作废与补开不改变资金事实，新旧凭证链、原因、操作者和时间可追溯。
- [ ] 冲正和退款后的当前资金状态正确，原始快照和凭证编号保持不变。
- [ ] 凭证不泄露非必要联系人、自由文本内部备注或中央审计敏感信息。
- [ ] 桌面与 360–390px 移动端可完成操作；浏览器打印与另存 PDF 经真实浏览器验证，正文无导航和交互控件。
- [ ] 展示模型不依赖浏览器 API，可被未来服务端渲染器直接复用。

## Dependencies and Out of Scope

- 依赖 `07-21-refund-approval` 与 `07-21-payment-reversals` 提供最终资金状态；在四个子任务中最后实施。
- 不提供电子发票、税务合规、签章、防伪验真、外部支付凭据、服务端 PDF、图片、邮件、批量打包、多笔合并或自动开具设置。
