# P1 消息通知、操作审计与导入导出

## Goal

让机构管理员能够追溯关键业务操作、在系统内接收待处理提醒，并安全地批量导入和导出招生线索；所有数据必须遵守现有的机构与校区访问边界。

## Confirmed Facts

- 系统使用 PostgreSQL + Drizzle、Hono + oRPC 和 React + TanStack Query。
- `organization_audit_event` 已记录机构、校区和成员管理操作，但动作枚举与读取能力尚未覆盖教培业务。
- 招生线索已具备按当前筛选条件导出 CSV 的服务端实现，前端直接下载 Blob。
- 所有业务读取均需要服务端根据当前成员解析机构和可访问校区，不能信任客户端机构 ID。

## Requirements

### R1. 操作审计

- 将审计能力扩展为机构级通用不可变流水，覆盖本期导入与通知已读，以及现有关键教培写入的可渐进接入。
- 管理角色可按动作、对象类型、操作者和时间范围查看审计记录；校区受限成员只能看到其可访问校区的记录。
- 审计记录保存动作、对象、操作者、可选校区、结构化前后快照和发生时间；快照不得包含密码、令牌或邀请原文。

### R2. 站内通知

- 提供持久化的站内通知收件箱，支持未读数、列表和单条/全部已读。
- 首批由系统在导入完成、导入存在错误和欠费跟进待办时生成站内通知；通知通过内部事件/投递接口创建，不把渠道逻辑散落到业务 repository。
- 通知投递必须具备请求幂等性；失败不能影响原始业务事务。

### R3. 线索导入与导出

- 提供 CSV 模板下载、预览校验和确认导入；导入至少支持姓名、手机号、意向课程、来源、负责人、跟进状态、备注和校区。
- 每行独立校验并返回可定位的错误；确认导入只写入有效行，并返回成功、跳过与失败统计。
- 导入必须使用当前机构和可访问校区；不得从文件信任机构、用户或权限字段。重复提交需由 requestId 保证幂等。
- 延续既有线索 CSV 导出，导出仅包含当前角色可访问的数据，并记录审计事件。

## Acceptance Criteria

- [ ] 管理员可在系统内筛选、分页查看审计记录；跨机构和越校区记录不会泄露。
- [ ] 用户可看到自己的未读通知、标记已读和全部已读；重复投递不会产生重复通知。
- [ ] 有权限的成员可以下载模板、预览 CSV、得到行级错误并确认导入有效行；重复确认不会新增重复线索。
- [ ] CSV 导出与导入均遵循原有机构、校区和角色授权，且生成对应审计记录。
- [ ] PostgreSQL 集成测试覆盖隔离、权限、幂等、行级校验和审计不可变性；Web 覆盖加载、空、错误与提交状态。

## Out Of Scope

- 外部短信、邮件、微信通知及真实第三方渠道凭据。
- 后台队列、大文件异步任务、附件导入、Excel 解析、复杂字段映射和跨实体批量导入。
- 审计记录的人工修改、删除或合规归档策略。
