## Goal

让合同、证件和收款材料等业务文件在系统内受控关联、查看和追溯，替代散落在本机或聊天工具中的材料，同时不把文件风险带入核心应用与数据库。

## Background

- 当前仓库没有对象存储或恶意文件扫描依赖，只有 PostgreSQL Docker Compose；附件能力需要新增可被后续报表复用的私有对象存储边界。
- Hono 的 `/rpc/*` 使用 256 KiB JSON body limit，不适合承载最大 10 MiB 的文件；现有服务端已有 Better Auth、可信 Origin、请求 ID 和当前机构上下文，可供独立流式文件路由复用。
- 运营任务提醒已提供 PostgreSQL `SKIP LOCKED`、租约、退避和多实例幂等 worker 模式；附件扫描和清理复用该算法，不引入外部队列或通用任务框架。
- `packages/ui` 已有 attachment 基础组件，但没有业务级上传、存储、扫描、授权或生命周期实现。

## Requirements

- PostgreSQL 只保存附件元数据、业务关联、对象键、大小、声明/检测 MIME、校验值、扫描状态、上传者、生命周期和审计信息；文件内容存入私有 S3 兼容对象存储。
- 本地开发由 Docker Compose 提供 MinIO；生产使用同一存储抽象接入兼容服务。服务端生成不可猜测对象键，不保存或返回永久公开 URL。
- 上传、预览和下载使用应用服务端流式代理与短时授权 ID，绑定机构、附件和当前用户；浏览器不直接获得 S3/MinIO 预签名 URL 或对象键。每次文件请求都重新校验当前 session、成员、校区和关联实体权限，成员撤权或附件归档后立即失效。
- 首期仅接受 PDF、JPEG、PNG，单文件最大 10 MiB；服务端同时检查扩展名、客户端声明 MIME、实际文件特征、字节数和 SHA-256。拒绝 SVG、HTML、Office、压缩包、脚本和可执行内容。
- 上传采用“创建元数据/授权上传 → 完成确认 → 隔离扫描 → 可用或拒绝”状态机。对象在扫描通过前不可预览、下载或参与业务导出。
- 生产环境必须配置恶意文件扫描器；未配置时上传入口不可用且给出运维可诊断错误，不得静默跳过。扫描失败/超时保持隔离并可受控重试，命中风险后拒绝并清理对象。
- 只有扫描和结构校验通过的 JPEG/PNG 可通过短时授权内联预览；PDF 首期仅允许安全下载，不在浏览器内联打开。响应使用安全的 `Content-Disposition`、受控文件名、`nosniff` 和私有缓存策略；在线 PDF 预览需后续增加服务端安全渲染或净化能力。
- 每个附件首期只允许绑定一个业务实体，通过带真实外键的类型化关联支持线索、学员、报名、账单、收款和收款凭证；不使用无外键的通用 `entityType + entityId`，也不允许跨多个关联扩大可见范围。关联实体的读/写权限决定可见和可上传范围，不提供绕过领域权限的机构级“全部文件”列表。
- 删除采用受权归档/解除关联并保留审计；已归档文件不再生成访问授权，对象保留 30 天后清理，元数据与审计永久保留。未完成上传 24 小时后清理；扫描失败保留 7 天供受控重试；命中恶意内容立即拒绝并在 24 小时内清理对象。所有清理均幂等且可观察。
- 文件名和说明等自由文本不复制进中央审计；中央审计只记录附件 ID、关联类型/ID、动作、状态和操作者。
- UI 覆盖上传进度、处理中、扫描失败、已拒绝、可预览、下载失败和归档状态，移动端可用且不会因大文件阻塞主页面。

## Acceptance Criteria

- [ ] PDF/JPEG/PNG 可在允许的业务实体下上传，超过 10 MiB、伪造类型或禁止格式在服务端被拒绝。
- [ ] 扫描前和扫描失败的对象不可访问；生产缺少扫描器时上传保持关闭，扫描通过后才可短时预览/下载。
- [ ] 跨机构、越权校区、无关联实体权限、成员撤权和过期授权均不能读取对象，且不会泄露对象是否存在。
- [ ] 对象键、存储凭证、预签名 URL 和永久公开 URL 不出现在客户端或数据库业务响应；对象键仅保存在服务端附件元数据中，数据库不保存文件二进制。
- [ ] 上传、关联、查看授权、归档、扫描和清理状态可追踪，失败重试/重复回调不会产生重复关系或孤儿对象。
- [ ] 本地 MinIO 开发环境、生产配置校验、对象生命周期和回滚说明可执行。
- [ ] 集成测试、类型检查、Biome、构建及桌面/390px 浏览器验证通过，并包含恶意类型与权限测试。

## Rollout and Rollback

- 先部署元数据 schema、存储配置校验和扫描器健康检查，再开放上传；生产配置不完整时入口保持关闭。
- 回滚应用时停止新上传和授权生成，保留元数据与私有对象；隔离/清理 worker 可独立停用，禁止通过删除表或桶回滚已上传材料。
