# P1 报名与财务变更能力

## Goal

让机构能在保留原始报名、应收、收款和课消历史的前提下，完成续费、转课、退费及人工欠费跟进，形成可审计且可重试的报名售后闭环。

## Confirmed Facts

- 现有 `enrollment` 保存已购/剩余课时和累计已收金额；`invoice` 与不可变 `payment` 是应收、收款事实来源。
- 已完成课次的扣课由唯一 `lessonConsumption` 账本保护，不能以直接改余额的方式回滚或重放。
- 财务和教务写入均须在事务内按当前成员、角色、校区范围重新授权；金额用分，业务日期按 `Asia/Shanghai`。
- 当前财务工作台已有账单检索、明细与收款登记，尚无报名变更、退款流水和欠费跟进入口。

## Requirements

### R1 续费

- 仅能为当前机构、当前可访问且启用校区内的有效报名续费。
- 一次续费追加明确的课时数，创建一张新的应收账单；原报名 ID、原账单、原收款和原课消均保留。
- 请求使用机构内唯一 `requestId` 幂等保护；重放相同请求返回同一结果，不同载荷复用 ID 必须失败。

### R2 转课

- 仅允许同一学员、同一机构、启用校区内的有效来源报名转入启用课程。
- 转课一次性转移来源报名的全部剩余课时，来源报名标记为已转出并脱离班级；创建一条目标课程报名和不可变转课记录。
- 为避免静默篡改既有应收，本期仅允许来源报名不存在未结清账单；不自动计算课程差价或创建补缴情单。

### R3 退费

- 退费以已结清账单为边界，创建不可变退款流水；累计退款不得超过该账单已收金额。
- 全额退款后账单标记为 `refunded`；部分退款保留其已结清状态并在 API/UI 明确展示退款金额和净收金额。
- 退款不能改写历史收款或课消，且按请求 ID 幂等。

### R4 欠费跟进

- 提供按当前成员校区范围隔离的欠费清单，展示应收、已收、欠款、到期日和最近一次人工跟进。
- 财务人员可追加一条人工跟进记录；本期不自动发送短信、邮件或微信通知。

### R5 交互与质量

- `/finance` 提供续费、转课、退费和欠费跟进入口，包含加载、空、错误、提交中与移动端状态。
- 所有写入均为事务，涵盖权限、机构隔离、校区停用、金额/课时边界、幂等与并发回归测试。

## Acceptance Criteria

- [ ] 续费会原子追加课时并创建独立账单；重复或并发相同请求不会重复追加。
- [ ] 转课不会更改历史收款/课消；欠费来源报名、跨机构/校区、停用课程或无剩余课时均被服务端拒绝。
- [ ] 退款流水不可变，累计退费不超过已收；全额退款后不能收款或再次退款。
- [ ] 欠费清单和跟进记录严格遵守机构、角色和校区边界。
- [ ] 数据库集成测试、类型检查、规范检查、构建和浏览器关键路径验证通过。

## Out Of Scope

- 外部支付网关原路退款、审批流、会计凭证、价格差自动结算、部分课时转移、跨机构转课。
- 自动化消息发送、统一操作审计、批量导入导出与财务报表。
