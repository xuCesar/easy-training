# P2 运营任务与提醒

## Goal

把工作台现有的只读任务快照扩展为可创建、分配、跟踪、完成和提醒的运营闭环，减少线下口头派单、聊天催办和重复登记。

## Background

- 数据库已有 `operation_task` 表，工作台只读取今日到期/逾期数据；当前没有任务 CRUD、状态历史、版本保护或提醒执行器。
- 系统已有站内通知和机构审计，可复用为提醒与关键操作追踪；没有通用后台队列或定时任务。

## Requirements

- 任务至少包含机构、可空校区、标题、可空说明、创建人、可空负责人、关联模块/实体、状态、截止时间、可空提前提醒、生效版本、完成/取消元数据和创建/更新时间。
- 状态固定为待处理、已完成、已取消；逾期是根据状态与截止时间派生的展示状态，不写成可漂移的第四种状态。
- 所有成员可创建并管理仅分配给自己的个人任务。owner/admin 可管理全机构任务，campus_manager 可管理授权校区任务；consultant/finance/teacher 不可给其他人派单。
- 只有管理角色可创建无负责人公共任务；成员认领后成为负责人。被分配人可完成自己的任务，创建人或相应管理角色可重开、改期、重新分配或取消。
- 分配/认领时服务端验证目标成员仍在当前机构、角色有效且具备任务校区及关联模块/实体访问权；客户端传入的 module/entity 不能绕过目标领域授权。
- 创建、编辑、认领、完成、重开、改期、重新分配和取消采用显式版本，陈旧版本返回结构化冲突，不覆盖其他人的更新；状态变化追加不可变历史。
- 列表支持我的任务、我创建的、公共待认领和管理范围筛选，以及状态、校区、关联模块、截止范围和关键词；工作台继续读取同一任务事实。
- 站内提醒包括：分配时立即通知；一次可选提前提醒（15 分钟、1 小时、1 天、3 天或受限自定义）；到期提醒；截止 24 小时后一次逾期提醒；完成时在创建人与负责人不同时通知创建人。
- 改期或重新分配后旧版本提醒失效并按新版本重新计算；完成/取消撤销所有待执行提醒。投递使用任务 ID、版本和提醒类型组成幂等键，重试不产生重复通知。
- 公共任务认领前不发送个人提醒；首期不每日重复催办，不发送邮件、短信或微信。
- 使用 PostgreSQL 持久待执行提醒和数据库租约，支持多实例唯一消费、短暂失败重试和进程重启后补偿；执行错误必须可观察且不改变任务状态。
- 关键任务动作写机构审计，但任务说明等自由文本不复制进中央审计。

## Acceptance Criteria

- [ ] 五类成员都能创建、查看、修改和完成本人任务；管理角色可在授权范围派单、重派、取消及管理公共任务。
- [ ] 越权分配、跨机构/校区、无关联实体权限、陈旧版本和非法状态跃迁均被服务端拒绝且无部分写入。
- [ ] 我的任务、公共任务、管理视图与工作台使用同一事实，筛选、分页、空/错/加载状态完整。
- [ ] 分配、提前、到期、逾期和完成提醒按规则各至多一次；改期、重派、完成和取消不会留下过期提醒。
- [ ] 两个实例并发消费及进程重启不会重复通知，失败有运行记录并可安全重试。
- [ ] 任务及状态历史可追溯，中央审计不包含任务说明等不必要自由文本。
- [ ] PostgreSQL 集成测试、类型检查、Biome、构建及桌面/390px 浏览器验证通过。

## Dependencies and Out of Scope

- 可独立于 T1 实施；完成后另行把运营任务接入全局搜索。
- 本任务建设的数据库租约执行基础由 T7 复用，但不实现报表计划。
- 不提供评论线程、子任务树、附件、工时、复杂 SLA、看板拖拽、重复任务、每日催办或外部通知渠道。

## Rollout and Rollback

- 以 additive migration 扩展现有 `operation_task`，先兼容工作台旧读取，再开放任务管理和提醒执行器。
- 回滚时可停止提醒租约执行并隐藏写入口，保留任务、状态历史和已投递通知；不得删除已创建任务或用逆向迁移抹除历史。
