# P2 运营任务与提醒实施计划

1. 读取现有 `operation_task`、工作台快照、通知和审计实现，确认 migration 与调用边界。
2. 设计并执行 additive migration：任务版本/完成取消元数据、不可变状态历史、提醒及租约字段与必要索引。
3. 实现 DB repository：授权范围、关联资源验证、事务化状态迁移、乐观锁和列表筛选。
4. 实现 API contracts、router 和错误映射；所有租户/校区/成员上下文来自服务端。
5. 实现提醒执行器与应用生命周期接线，保证租约、幂等、重试和可观察错误。
6. 实现任务管理界面与工作台入口，复用现有通知和列表组件模式。
7. 增加 PostgreSQL 集成测试、类型/格式/构建与桌面/390px 验证；同步相关规范。

## 验收门槛

- 任一写操作必须验证旧版本，且失败不会写 history、reminder 或审计。
- 多实例领取同一提醒只能产生一次站内通知。
- 完成/取消任务后，旧提醒不可再被领取。
