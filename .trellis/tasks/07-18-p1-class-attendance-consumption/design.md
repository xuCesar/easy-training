# P1 技术设计：入班、考勤与课时消耗

## 数据模型

- 继续使用 `enrollment.classGroupId` 作为入班归属，不新增平行成员表。
- 保留现有 `attendance`，新增必要的机构审计字段和按课次读取索引。
- 新增 `lessonConsumption` 账本，使用 `(enrollmentId, lessonId)` 唯一约束，保存前后课时、考勤状态、操作者和时间；它是余额变更的唯一审计事实。

## 写入流程

`completeLesson` 在机构 advisory lock 与事务内：重新解析成员和校区范围 -> 锁定课次、班级和当前报名 -> 校验课次为 `scheduled`、名单完整且成员/校区一致 -> 预检所有需消课报名的余额 -> 写入考勤 -> 创建消耗账本 -> 扣减余额 -> 将课次改为 `completed`。

任一步失败时整个事务回滚。已完成或已取消课次不进入该流程，因此重复和并发请求没有第二次扣减路径。

## API 与 UI

- 教务 repository 负责入班列表、归属更新、课次点名详情和结课事务；API 仅转换 DTO 和领域错误。
- 课程/班级/课次查询扩展必要的成员和消课摘要，不将 schema 直接暴露给 Web。
- Web 在现有 `/academic` 中增加班级成员管理与课次点名弹窗，沿用 oRPC、TanStack Query 和现有对话框组件。

## 兼容与回滚

迁移仅追加表、字段和索引；已有报名仍可无班级归属，已有已完成课次不回填考勤或消课。回滚应用版本不会删除历史流水。
