# P2 报表导出与定时报表

## Goal

让用户保存常用经营筛选、按同一指标口径导出结果，并以可追踪的每日/每周/每月计划生成私有报表，减少重复设置和人工定期汇总。

## Requirements

### Saved Views and Export

- 有权访问分析页面的成员可保存、重命名、应用和删除本人的筛选条件；保存内容只包含受控 report kind、时间预设/自定义范围、维度和筛选值，不保存任意 SQL、URL 或当前权限快照。
- 应用保存条件时按当前角色、校区、可用维度和指标版本重新校验；已撤权或失效筛选返回明确提示并忽略非法范围，不能恢复历史权限。
- 即时导出复用 T5/T6 的同一服务端查询、排序、时间口径和指标版本；首期每次导出一个报表视图为 UTF-8 BOM CSV，包含生成时间、时区、范围和指标版本元数据。
- CSV 对公式前缀转义，有明确行数/时间范围上限，不包含页面未授权的隐藏列或敏感自由文本。请求人、筛选摘要、结果数、状态和文件标识可审计。
- 小结果可同步下载；超过同步阈值时创建报表运行并使用与定时报表相同的异步路径，避免绕过请求/响应大小边界。

### Schedule and Execution

- 计划持久化 report kind、保存条件快照、频率、上海时区执行点、下一次执行时间、启用状态、创建人和版本；频率只支持每日、每周、每月，不接受任意 Cron。
- 任一有权访问对应报表的角色都可为本人创建计划；每次执行都以创建人的当前成员身份、角色和校区范围重新授权。成员被移除、角色无权或筛选全部失效时运行失败且不生成文件。
- PostgreSQL 保存运行记录、计划版本、计划触发时间、实际开始/结束时间、筛选快照、指标版本、状态、结果数、对象 ID和受控失败原因。
- 复用 T2 的数据库租约执行器，保证多实例同一计划时点只执行一次；重启后最多补最近一次遗漏，不追赶生成大量历史文件。
- 支持停用、恢复和对失败运行手动重试；重试创建新的运行尝试并引用原运行，不覆盖历史。计划修改只影响后续运行。
- 完成/失败通过站内通知告知创建人；首期不发送邮件、短信或微信。

### Storage and Lifecycle

- 报表文件写入 T4 私有对象存储，客户端只通过当前授权的短时下载链接访问；对象键、存储凭证和永久 URL 不暴露。
- 默认保留 30 天，过期后对象清理但运行元数据继续保留并显示“文件已过期”；清理、重复回调和重试均幂等。
- 下载时重新验证当前成员和运行归属/管理范围；历史通知或已保存 URL 不能绕过权限收回。
- 报表生成失败不产生看似成功的空文件；真实零结果可以成功并在元数据和文件中明确标记。

## Acceptance Criteria

- [ ] 成员可保存、应用、重命名和删除本人筛选；权限或维度变化后不会恢复越权范围，并有可理解提示。
- [ ] 页面和 CSV 对相同筛选返回相同口径、排序、范围和指标版本；CSV 防公式注入且不含隐藏列/敏感文本。
- [ ] 每日/每周/每月计划按 Asia/Shanghai 生成可追踪运行，多实例并发和重启补偿不会重复生成同一时点报表。
- [ ] 每次运行重新授权并固化筛选快照、指标版本和生成时间；撤权、无权和真实空结果具有不同状态。
- [ ] 报表文件私有、短时下载、30 天过期，过期和权限收回后旧链接不可读取；清理不删除运行历史。
- [ ] 停用、恢复、失败手动重试和站内成功/失败通知正确，重试不覆盖原运行。
- [ ] PostgreSQL/对象存储集成测试、租约并发测试、类型检查、Biome、构建及桌面/390px 浏览器验证通过。

## Dependencies and Out of Scope

- 依赖 T2 数据库租约执行基础、T4 私有对象存储，以及 T5/T6 统一指标查询和版本；在这些契约稳定后实施。
- 首期只导出 CSV，不提供 Excel/XLSX、PDF 排版、压缩包、任意 SQL、任意 Cron、邮件附件、外部分享、公开链接或 P3 外部通知渠道。

## Rollout and Rollback

- 先部署计划/运行 schema 和手动即时导出，再以默认停用的 worker 验证租约、对象写入和通知，最后允许创建定时计划。
- 回滚时停用所有计划和 worker、停止生成新文件，保留运行历史和未过期私有对象；30 天生命周期清理仍可独立执行。
