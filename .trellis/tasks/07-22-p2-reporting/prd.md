# P2 保存筛选与即时 CSV 导出

## Goal

让有权访问经营分析的成员保存个人常用筛选，并从当前分析结果即时导出同口径、同权限、同排序的 CSV，减少重复设置与手工复制汇总。

## Background

- 当前研发环境可以完整验证数据库配置、查询权限、同步响应和浏览器下载。
- 仓库暂不具备生产对象存储、持久报表 worker、文件保留策略和外部投递条件。
- 因此当前任务不再包含异步大结果和定时报表；这些能力作为后续独立需求排期。

## Requirements

### Saved Filters

- 有权访问分析页面的成员可保存、重命名、应用和删除本人的筛选条件。
- 保存内容只包含受控 report kind、时间预设/自定义范围、维度、排序和筛选值，不保存任意 SQL、任意 URL、页面缓存或当前权限快照。
- 应用时按当前角色、校区、可用维度和指标版本重新校验；成员撤权、维度失效或范围越权时给出明确提示，不能恢复历史权限。
- 保存筛选按机构和成员隔离；其他成员不能读取、修改或推断其名称与内容。

### Immediate CSV Export

- 导出复用经营分析页面的同一服务端查询、排序、时间口径和指标版本，前端不重新聚合或拼接隐藏数据。
- 首期每次只导出一个当前报表视图，格式为 UTF-8 BOM CSV，并包含生成时间、时区、查询范围和指标版本等必要元数据。
- 服务端对公式前缀进行转义，不导出未授权隐藏列、敏感自由文本或可用于推断隐藏对象的数据。
- 导出设置明确的最大时间范围、最大行数和响应大小；超限时返回可理解错误并提示缩小筛选，不创建后台任务或伪装成成功空文件。
- 下载请求每次按当前成员身份重新授权；页面曾经可见或保存过筛选不代表继续拥有导出权限。
- 审计记录请求人、报表类型、筛选摘要、结果行数和成功/失败状态，不记录完整敏感内容。

## Acceptance Criteria

- [ ] 成员可保存、应用、重命名和删除本人筛选，跨成员与跨机构访问被服务端拒绝。
- [ ] 权限、校区或维度变化后，保存筛选不会恢复旧范围，并显示明确失效提示。
- [ ] 页面和 CSV 对相同筛选返回相同口径、排序、范围和指标版本。
- [ ] CSV 使用 UTF-8 BOM、阻断公式注入且不含隐藏列或敏感自由文本。
- [ ] 时间范围、行数或响应大小超限时明确失败，不生成误导文件或后台任务。
- [ ] PostgreSQL 集成测试、权限测试、类型检查、Biome、构建及桌面/390px 浏览器验证通过。

## Dependencies and Out of Scope

- 依赖核心经营指标、财务分析、资源利用和多维经营对比的统一服务端查询契约。
- 当前阶段不提供异步大结果、定时报表、后台 worker、对象存储文件、文件保留、外部发送、公开分享或失败重试队列。
- 不提供 Excel/XLSX、PDF、压缩包、任意 SQL、任意 Cron 或跨机构报表。

## Future Scheduling Requirement

完整定时报表后续独立规划，启动条件至少包括：私有对象存储、稳定的后台 worker、多实例调度/幂等策略、文件保留与清理、生产监控和明确投递渠道。届时复用本任务的保存筛选和统一查询，不改写当前契约。
