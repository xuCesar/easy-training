# 安全事件响应流程

> 状态:草稿 v0.1(2026-07-26)。适用于试运行期(单实例、单运维人)。

## 一、适用事件

- 个人信息泄露、篡改、丢失(数据库拖库、备份泄露、越权访问)
- 服务器失陷(异常进程、未知登录、面板被入侵)
- 凭据泄露(数据库口令、COS 密钥、BETTER_AUTH_SECRET、SSH 私钥、SES 密钥)
- 勒索/删库等破坏性事件

## 二、角色与责任人

| 角色 | 责任人 | 职责 |
| --- | --- | --- |
| 事件负责人 | *[机构/系统负责人,待确认]* | 决策、对外通知 |
| 技术处置 | *[同上或运维协作者]* | 止损、取证、恢复 |

## 三、处置步骤

**1. 止损(发现后立即)**

- 服务下线:`pm2 stop easy-training`;必要时在腾讯云防火墙关闭 80/443
- 凭据轮换(按泄露面):数据库角色口令、BETTER_AUTH_SECRET(会使全部会话失效)、
  COS 密钥(控制台禁用)、SSH 密钥、宝塔面板口令
- 保留现场:不要清空日志;为服务器打快照(轻量服务器控制台)

**2. 评估(24 小时内)**

- 影响范围:哪些表/多少学员的个人信息可能被访问;时间窗口
- 依据:nginx 访问日志、应用 `http.access` 结构化日志(含 requestId)、
  PostgreSQL 日志、`last`/`journalctl` 登录记录、审计事件表
- 判定级别:仅系统受影响(未触及个人信息)/ 个人信息可能泄露 / 确认泄露

**3. 通知**

- 确认或高度疑似个人信息泄露:*[24 小时]* 内通知机构负责人;
  由机构通知受影响监护人(说明泄露类别、可能影响、已采取措施、联系方式)
- 按《个人信息保护法》第五十七条向履行个人信息保护职责的部门报告
- 涉及刑事犯罪(勒索、入侵)同时报警

**4. 恢复**

- 从加密备份恢复(流程见 `ops/backup/README.md`,已演练);
  恢复前确认备份点早于入侵时间
- 全量凭据轮换后重新上线;上线后 48 小时加强观察

**5. 复盘(7 日内)**

- 成因、时间线、影响、整改项(含代码/配置修复)写入事件记录,
  存放于 *[机构指定位置]*;整改项开 GitHub issue 跟踪

## 四、演练

每 *[半年]* 做一次桌面演练(walkthrough):凭据轮换 + 备份恢复 + 通知模板过一遍。
